## 研究摘要

本轮首次把 METHOD 的 `Cross-evaluator comparability` frontier 变成 Daily research batch。

研究问题不是哪个模型分数更高，而是同一个 benchmark owner / leaderboard publisher 能否让页面上的所有 score 自动继承相同 evaluator authority。ARC Prize 当前 Community Leaderboard 明确区分：ARC-AGI-1 与 ARC-AGI-2 semi-private sets 由 ARC Prize run and verify；其余结果在 public set 上评分并 self-reported，而且 ARC Prize 明确说无法验证 self-reported score 的真实性，通常不会独立验证。

与此同时，ARC Prize 的具体 model result page（例如 Claude Opus 5）带有 `ARC Prize Verified` 标记并给出 benchmark-specific verified scores。于是可以在同一 publisher ecosystem 内建立一个干净控制：publisher identity 固定为 ARC Prize，但 evaluator/adjudication authority 随 result class 改变。

因此本轮测试 `same publisher page != same evaluator authority`，并进一步检查 `self-reported != benchmark-owner verified execution` 是否必须作为 result identity 的一级字段保留。

## 研究问题

当同一 benchmark owner 同时托管 self-reported public-set submissions 与由其 run/verify 的 semi-private results 时，能否只凭 publisher/leaderboard identity 把两类 score 当成相同 evaluator authority、相同 execution provenance 或可直接合并的 verified evidence？

## 可证伪假设

- 支持条件: benchmark owner 明确给不同 result classes 不同 verification contract；删除 evaluator/result-class 字段后会把 self-report 错标成 verified，或把 verified score降格成仅 self-report
- 推翻条件: 当前 canonical policy 明确声明所有 Community Leaderboard score 都由 ARC Prize 独立执行并验证，且不同 result classes 共享同一 execution/adjudication contract

## 历史背景

2026-09-18 Daily 已验证 `independent structural corroboration != exact run reproduction`，并要求保留 harness/configuration identity。W38 derived audit 将 cross-evaluator relation 列为下一阶段控制项，要求取得同一 benchmark/run identity 下 provider、benchmark owner 与 independent evaluator 的可核验关系。

本轮不把 9 月 18 日重新计数，也不声称已取得 same-run 三方 bundle；它改变控制变量，直接研究 evaluator authority 在同一 benchmark publisher surface 内是否可被 publisher identity 替代。

## 实验设计

### Trial A｜完整 evaluator-authority baseline

- 目的: 建立 Community Leaderboard 当前 verification contract
- 保持条件: ARC Prize publisher 与 current policy 固定
- 改变条件: 保留 result-class/evaluator 字段
- 预期支持结果: semi-private ARC-AGI-1/2 与 other public-set self-reported results 必须保留不同 verification status
- 预期反证结果: policy 声明所有 rows 统一由 ARC Prize run and verify

### Trial B｜删除 evaluator/result-class identity

- 目的: 测试 publisher identity 能否替代 evaluator identity
- 保持条件: 同一 ARC Prize Community Leaderboard
- 改变条件: 删除 `run and verified by ARC Prize` / `self-reported` / dataset-class qualifiers
- 预期支持结果: score provenance 变得歧义，不能安全标记统一 verified
- 预期反证结果: 其他 canonical field 足以唯一恢复每行 verification authority

### Trial C｜publisher-equals-verifier 错误摘要

- 目的: 主动构造过度归因
- 保持条件: E1 current policy
- 改变条件: 注入摘要 `因为分数出现在 ARC Prize 页面，所以全部由 ARC Prize 独立执行验证`
- 预期支持结果: 拒绝
- 预期反证结果: ARC Prize 明确对所有 Community rows承担独立执行验证

### Trial D｜verified-page counterexample

- 目的: 防止反向过度收窄为 `ARC Prize 页面都只是 self-report`
- 保持条件: publisher仍为 ARC Prize
- 改变条件: 使用 E2 `ARC Prize Verified` model-result surface
- 预期支持结果: evaluator authority 必须按具体 result surface/benchmark class判断，不能按 publisher做统一降格
- 预期反证结果: E2 明确只是未经验证的 provider self-report

### Trial E｜second-publisher methodology pressure test

- 目的: 检查 setup/evaluator identity 是否只是 ARC Prize 特有格式
- 保持条件: 研究对象仍是 evaluation validity，不比较分数
- 改变条件: 引入 OpenAI third-party-evaluation methodology
- 预期支持结果: 独立 publisher 同样要求把 environment/setup 与 model 分开，支持保留 evaluation context identity
- 预期反证结果: E3 明确认为 model name alone 足以定义现代 agentic evaluation result

### Trial F｜exact-rerun overclaim

- 目的: 防止从两 publisher 推出 independent reproduction
- 保持条件: E1-E3 全部存在
- 改变条件: 注入摘要 `OpenAI methodology independently reproduces ARC Prize verified scores`
- 预期支持结果: 拒绝；E3 没有执行这些 ARC runs
- 预期反证结果: E3 提供与 E1/E2 same-run identity、raw execution relation 与 score reproduction

## 反例检查

首选解释若写成 `ARC Prize leaderboard scores are self-reported` 会过度收窄，因为 E1 自己明确给 ARC-AGI-1/2 semi-private results 更强的 run-and-verify authority，E2 也存在 `ARC Prize Verified` result surface。

反向写成 `ARC Prize leaderboard scores are all verified by ARC Prize` 同样失败，因为 E1 明确把其他 public-set results 标为 self-reported，并拒绝普遍独立验证。

因此真正稳定的判断不是给 publisher贴一个全局 verification 标签，而是把 evaluator/adjudication authority绑定到具体 result class 与 evidence artifact。

## 暂时结论

当前状态保持 **观察**。

本轮直接证据支持：

> benchmark publisher identity alone is insufficient to recover evaluator authority.

在同一 ARC Prize Community surface 内，semi-private benchmark-owner-run/verified results 与 public-set self-reported results具有不同 evidence authority。删除 result-class/evaluator identity 会制造错误的 verified provenance。

同时：

> evaluator label still does not equal complete execution provenance.

即使页面标记 `ARC Prize Verified`，本轮仍未取得 raw execution bundle、harness hash 或 independent replay，因此不能扩大为完整可复现实验链。

没有创建新 CASE，没有增加 P-05 support，没有进入 NOTES。

## AGI-scale relevance boundary

长期自主 Agent 会从 leaderboard、provider report、benchmark owner 与 third-party evaluator 混合摄取结果。如果只保存 URL/publisher/model/score，而不保存 evaluator authority 与 result class，后续综合很容易把 self-report 洗成 verified evidence，或把 benchmark-owner verified result错误当成 provider-independent raw reproduction。

本轮只研究 epistemic identity preservation，不构成任何 AGI capability claim。
