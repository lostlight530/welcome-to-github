## 研究摘要

本轮首次把 METHOD 的 `Cross-evaluator comparability` frontier 变成 Daily research batch，并在同一上海日期内继续补强同一记录。

研究问题不是哪个模型分数更高，而是同一个 benchmark owner / leaderboard publisher 能否让页面上的所有 score 自动继承相同 evaluator authority。ARC Prize Community Leaderboard 明确区分 ARC-AGI-1/2 semi-private 的 benchmark-owner run/verified 结果与其他 public-set self-reported 结果；ARC Prize model result surface 又存在 `ARC Prize Verified` 标记。

同日补强进一步直接读取 ARC Prize Verified Testing Policy。该 policy 将 Verified Leaderboard 与 Community Leaderboard 分开，说明 ARC Prize 对选定模型执行测试；Community submissions 默认不验证；verified evaluation 使用 single run，不跨 runs 取平均。这个新控制使 `verified` 的语义边界更清楚：它可以建立 benchmark-owner evaluation authority，但不能自动升级成 repeated reproduction、variance estimate 或 raw-run transparency。

因此本轮最终测试的是：

`same publisher != same evaluator authority`

`verified != repeated reproduction`

`verified != complete raw execution provenance`

## 研究问题

当同一 benchmark owner 同时托管 self-reported public-set submissions、benchmark-owner run/verified results 与正式 Verified Leaderboard testing policy 时，能否只凭 publisher/leaderboard identity 把这些 score 当成相同 evaluator authority、相同 execution provenance、重复复现或可直接合并的 verified evidence？

## 可证伪假设

- 支持条件: benchmark owner 明确给不同 result classes 不同 verification contract；删除 evaluator/result-class 字段会制造错误 provenance；verified policy 本身不提供 repeated-run relation
- 推翻条件: canonical policy 明确声明所有 Community scores 都由 ARC Prize 独立执行验证，并且 `Verified` 明确等价于多个独立 runs、完整 raw bundle 与 independent third-party reproduction

## 实验设计

### Trial A｜完整 evaluator-authority baseline

- 目的: 建立 Community Leaderboard 当前 verification contract
- 保持条件: ARC Prize publisher 与 current policy 固定
- 改变条件: 保留 result-class/evaluator 字段
- 预期支持结果: semi-private run/verified 与 public-set self-reported 保持不同 authority
- 预期反证结果: policy 声明所有 rows 统一由 ARC Prize run and verify

### Trial B｜删除 evaluator/result-class identity

- 目的: 测试 publisher identity 能否替代 evaluator identity
- 保持条件: 同一 Community Leaderboard
- 改变条件: 删除 `run and verified` / `self-reported` / dataset-class qualifiers
- 预期支持结果: provenance 歧义，不能安全标记统一 verified
- 预期反证结果: 其他 canonical field 足以唯一恢复每行 authority

### Trial C｜publisher-equals-verifier 错误摘要

- 目的: 主动构造过度归因
- 保持条件: E1 current policy
- 改变条件: 注入 `因为分数出现在 ARC Prize 页面，所以全部由 ARC Prize 独立执行验证`
- 预期支持结果: 拒绝
- 预期反证结果: policy 对全部 Community rows 承担独立执行验证

### Trial D｜verified-page counterexample

- 目的: 防止反向过度收窄为 `ARC Prize 页面都只是 self-report`
- 保持条件: publisher 仍为 ARC Prize
- 改变条件: 使用 E2 `ARC Prize Verified` result surface
- 预期支持结果: authority 必须按具体 result surface / benchmark class 判断
- 预期反证结果: E2 明确只是未经验证的 provider self-report

### Trial E｜second-publisher methodology pressure test

- 目的: 检查 evaluation-context identity 是否只是 ARC Prize 特有格式
- 保持条件: 不比较分数
- 改变条件: 引入 E3
- 预期支持结果: 独立 publisher 同样要求 environment/setup identity
- 预期反证结果: E3 明确认为 model name alone 足以定义 agentic evaluation result

### Trial F｜exact-rerun overclaim

- 目的: 防止从两 publisher 推出 independent reproduction
- 保持条件: E1-E3 全部存在
- 改变条件: 注入 `OpenAI methodology independently reproduces ARC Prize verified scores`
- 预期支持结果: 拒绝
- 预期反证结果: E3 提供 same-run identity 与 score reproduction

### Trial G｜verified-equals-replicated pressure test

- 目的: 检查 `ARC Prize Verified` 能否自动解释为重复复现
- 保持条件: E2 verified surface 与 E4 verification policy 固定
- 改变条件: 注入 `Verified means multiple independent ARC Prize runs reproduced the score`
- 预期支持结果: 拒绝；E4 明确说明 a single run is used and scores are not averaged across runs
- 预期反证结果: E4 或目标 result surface提供多个独立 runs、repeat-run IDs 或 variance/aggregation relation

## 反例检查

首选解释若写成 `ARC Prize leaderboard scores are self-reported` 会过度收窄，因为 E1 明确给 ARC-AGI-1/2 semi-private results 更强的 run-and-verify authority，E2 也存在 `ARC Prize Verified` surface。

反向写成 `ARC Prize leaderboard scores are all verified by ARC Prize` 同样失败，因为 E1/E4 都把 Community default 与 verified testing 分开。

进一步写成 `ARC Prize Verified means replicated across multiple independent runs` 也失败：E4 明确说明 verified evaluation 使用 single run，不跨 runs 取平均。因此 `verified` 与 `replicated` 必须保留不同 identity。

稳定判断不是给 publisher 或 `Verified` 标签附加全局含义，而是把 evaluator authority、result class、run count 与 evidence artifact 分开。

## 暂时结论

当前状态保持 **观察**。

本轮直接证据支持：

> benchmark publisher identity alone is insufficient to recover evaluator authority.

以及同日补强后的更窄边界：

> benchmark-owner verification is stronger provenance than default self-report, but verification does not by itself establish repeated independent reproduction or complete raw execution provenance.

这不是说 ARC Prize verified result 不可信；相反，E4 给出了更明确的 benchmark-owner testing authority。研究边界只是拒绝把 `Verified` 扩大为 policy 没有声明的 multiple-rerun、variance 或 independent third-party reproduction。

没有创建新 CASE，没有增加 P-05 support，没有进入 NOTES。

## AGI-scale relevance boundary

长期自主 Agent 会混合摄取 leaderboard、provider report、benchmark owner 与 third-party evaluator 结果。如果只保存 URL/publisher/model/score/verified badge，而不保存 evaluator authority、result class 与 run-count identity，后续综合可能把 self-report 洗成 verified evidence，也可能把 single benchmark-owner verification 洗成 repeated independent reproduction。

本轮只研究 epistemic identity preservation，不构成任何 AGI capability claim。
