## 研究摘要

本日研究一个 runtime-budget shortcut：给 model call 配置 timeout，是否就足以证明整个 Agent run、tool execution 与 retry/backoff 都被同一个 deadline 约束

OpenAI Agents SDK current contract 明确说明 `ModelSettings.timeout` 只限制每一次 model-call attempt，覆盖该 attempt 的 transport wait，但不限制 full agent run、function-tool execution 或 retry backoff

同一 contract 还说明每次允许的 retry 都获得新的 per-attempt timeout；tool execution 与 runner turn budget 又是独立 runtime surfaces

因此本轮 bounded result 是：per-attempt model timeout 不是 end-to-end run deadline。证据足以否定 `MODEL_TIMEOUT == FULL_RUN_BUDGET` shortcut，但只有一个 publisher family，且没有 wall-clock runtime，所以保持 PARTIAL

## 研究问题

`ModelSettings.timeout` 是否能够单独证明整个 Agent run 在同一 wall-clock deadline 内结束，还是 model attempt、retry/backoff、tool execution 与 run-loop budget 必须分别建模

## 实验设计

### Trial A

- 目的: 测试 model-call timeout 是否覆盖 full agent run
- 保持条件: 同一个 model timeout 配置
- 改变条件: 单次 model attempt 对比完整 runner loop
- 预期支持结果: contract 明确排除 full run
- 预期反证结果: timeout 被定义为整个 run 的 wall-clock deadline

### Trial B

- 目的: 测试 model-call timeout 是否覆盖 retry/backoff
- 保持条件: 同一个 timeout 值
- 改变条件: initial attempt 对比 retry attempts 与 backoff
- 预期支持结果: 每次 retry 获得新的 per-attempt timeout
- 预期反证结果: initial timeout deadline 持续覆盖全部 retry/backoff

### Trial C

- 目的: 测试 model timeout 与 tool/run-loop budget 是否同一 coordinate
- 保持条件: 同一个 agent workflow
- 改变条件: model attempt、function-tool execution 与 max-turn loop
- 预期支持结果: contract 暴露独立 ToolTimeoutError / max_turns boundary
- 预期反证结果: model timeout 自动成为 tools 与 runner loop 的统一 budget

## 原始观测

1. `ModelSettings.timeout` 是每次 model-call attempt 的最大持续时间
2. timeout 覆盖 streaming/non-streaming model attempt 与 transport waits
3. 文档明确它不限制 full agent run、function-tool execution 或 retry backoff
4. 每一个允许的 retry attempt 获得新的 per-attempt timeout
5. `backoff.max_delay` 只限制计算得到的 backoff，不自动限制 explicit policy delay 或 retry-after hint
6. runner 将 model loop、tool calls 与 handoffs 分为不同阶段，并用 `max_turns` 提供独立 turn boundary
7. runtime errors 区分 `ModelTimeoutError` 与 `ToolTimeoutError`
8. 本轮没有运行 Agents SDK、没有 wall-clock trace，也没有执行 retry/tool timeout matrix

## 暂时结论

当前状态为 PARTIAL

```text
PER_ATTEMPT_MODEL_TIMEOUT
!= END_TO_END_AGENT_RUN_BUDGET
```

长期 Agent 的 deadline accounting 至少应分别记录 model-attempt timeout、tool timeout、retry/backoff policy、turn budget 与 outer workflow deadline

由于只有一个 publisher family 且没有 runtime timing，本轮不推广为跨框架普遍实现事实，也不量化 production latency 或 deadline reliability

## AGI-scale relevance boundary

长期自主 Agent 的 hard budget 不能只在 model request 层设置一个 timeout 就宣称整个任务有 deadline

当 workflow 包含 tools、retries、handoffs、approval waits 或 durable orchestration 时，budget 必须沿 runtime layers 显式传播并可观测

本轮只建立 timeout scope 与 evidence boundary，不构成模型能力或具体系统 SLA 声明
