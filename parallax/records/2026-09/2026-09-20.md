## 研究摘要

本轮第一次把 METHOD 中 `World-state drift during deliberation` frontier 变成 Daily research batch.

研究对象不是服务是否最终恢复这一简单事实, 而是长期 Agent 在 S0 读取动态状态、经过一段 deliberation 后世界进入 S1 时, 原计划和事实绑定是否仍然合法.

OpenAI Status 对同一 incident 给出可排序的状态链. 2026-09-18 10:29 PM 的 Investigating 更新称正在调查 OpenAI-hosted containers in Agent API 的 higher-than-expected charges, 正在准备 refunds. 11:22 PM 仍在修复, 同时 reviewing affected usage to identify impacted customers and calculate refunds. 2026-09-19 01:08 AM 进入 Identified, 05:00 AM 进入 Monitoring, 明确 mitigation 已应用且 `any new sessions would not run into this issue`; 07:52 AM 进入 Resolved, 写明 all impacted services have now fully recovered.

这提供一个干净的 temporal control: S0 的历史判断可以在其时间切片内保持真实, 但 current decision 在 S1 不能继续使用 `still investigating` 或 `still implementing mitigation` 作为当前事实. 同时 terminal `Resolved` 只直接解决 incident/service current state, 不能自动补出 earlier refund-review workflow 的 per-customer terminal evidence.

因此本轮测试的是 `historical truth`, `decision-time truth`, `execution-time truth` 与 `remediation-object truth` 是否会在长推理中被错误压成一个状态.

## 研究问题

当 Agent 在动态 incident 的 S0 建立计划, 但在 action/conclusion 前同一 canonical object 已进入 S1 terminal state 时, 是否必须重新绑定 current-state evidence; 重新绑定后, 是否仍能保留 S0 的历史事实而不把 aggregate `Resolved` 扩大成每个 remediation object 已完成

## 可证伪假设

- 支持条件: 同一 incident 的 later terminal update 改变 current-state judgment; S0 历史文本继续作为 point-in-time truth; 删除 terminal update 后不能声称 current resolved; 恢复 terminal update后也不能从 aggregate recovery 推出每个退款完成
- 推翻条件: 当前 canonical evidence 表明 S0 与 S1 没有 material state change, 或 terminal update 明确逐项确认所有受影响 usage review、refund calculation、refund issuance 与到账均完成

## 实验设计

### Trial A｜S0 historical baseline

- 目的: 建立长推理开始时可合法存在的旧状态
- 保持条件: incident identity 固定
- 改变条件: evidence cut 截止 2026-09-19 01:08 AM Identified
- 预期支持结果: 可以写 `mitigation still being implemented` 作为该时点事实, 不能写 Resolved
- 预期反证结果: 01:08 AM 之前已有同一 incident 的 terminal resolution evidence

### Trial B｜S1 current-state rebinding

- 目的: 检查 action 前重新读取是否改变 current judgment
- 保持条件: 同一 incident identity
- 改变条件: evidence cut 推进到 07:52 AM Resolved
- 预期支持结果: current judgment 更新为 Resolved/fully recovered, `still implementing mitigation` 不再是 current truth
- 预期反证结果: terminal update 不属于同一 incident 或被 later correction 撤回

### Trial C｜删除 terminal update

- 目的: 测试是否会从相邻 Monitoring 自动补出 Resolved
- 保持条件: 保留 05:00 AM Monitoring 与 earlier updates
- 改变条件: 删除 07:52 AM Resolved 与 E2 history terminal row
- 预期支持结果: 最强状态只能是 Monitoring; 不得把 mitigation + new-session statement 推成正式 Resolved
- 预期反证结果: remaining canonical evidence 仍直接声明同一 incident 已 Resolved

### Trial D｜historical rewrite counterexample

- 目的: 检查 later resolution 是否会删除 S0 truth
- 保持条件: 完整 E1 timeline
- 改变条件: 注入摘要 `因为最终 Resolved, 所以 01:08 AM 时 incident 实际已经 resolved`
- 预期支持结果: 拒绝; later state 只更新 current judgment, 不改写 earlier point-in-time state
- 预期反证结果: provider 明确 correction earlier timestamp/state as erroneous

### Trial E｜refund-completion overclaim

- 目的: 检查 aggregate recovery 是否会被扩大到 remediation objects
- 保持条件: 完整 timeline, 包括 earlier `reviewing affected usage`, `calculate refunds` 与 final `fully recovered`
- 改变条件: 注入摘要 `Resolved means every affected customer refund has completed`
- 预期支持结果: 拒绝; final update 没有逐项给出 refund issuance/receipt terminal evidence
- 预期反证结果: canonical terminal update 明确声明所有 affected refunds completed/received

### Trial F｜decision-time policy comparison

- 目的: 测试 no-reread 与 selective-reread 对 current action premise 的差异
- 保持条件: 同一 incident, 同一历史 S0 evidence
- 改变条件: Path 1 在 action 前不重读; Path 2 只重读同一 canonical incident terminal state
- 预期支持结果: Path 1 可能继续携带 stale `Identified` premise; Path 2 可更新 current incident state, 同时保留 refund unknown
- 预期反证结果: S0→S1 没有任何 action-relevant state change

## 反例检查

最强反例不是 `Resolved 可能是错的`, 而是 `S0 statement can remain historically true while becoming unusable as current action premise`.

Trial D 主动尝试用 later Resolved 删除 earlier Identified, 被 timestamped same-incident timeline 反驳.

Trial E 主动尝试把 incident-level recovery扩成每个 refund completion. 当前 terminal update 没有提供该粒度证据, 因而结论必须收窄为 UNKNOWN, 但不能反向声称 refunds 未完成.

另一个重要反例是 05:00 Monitoring 已经明确 `any new sessions would not run into this issue`. 因此也不能把 `not yet Resolved` 机械解释为 `new sessions still affected`. 状态标签与 action-specific predicate 必须分别读取.

## 暂时结论

**观察**.

在本轮同一 canonical incident 中, world state 从 Investigating/Identified 推进到 Monitoring 再到 Resolved. 对长期 Agent 来说, 一个在 S0 合法建立的 current-state premise 在 action 前可能已经 stale; 对 current-state claim 的最小安全操作是重新读取同一对象的最新 authoritative state cut, 而不是让 deliberation 开始时的 snapshot 永久绑定整个任务.

同时, rebinding 只更新被 later evidence 直接覆盖的 proposition. 07:52 AM `fully recovered` 支持 incident/service current state 已恢复, 但本轮所读 terminal text不足以把 earlier refund review/calculation workflow扩成 `every affected customer refund completed`.

因此当前窄边界是:

`historical truth can remain true while current action premise becomes stale`

`current-state rebinding != historical rewrite`

`terminal incident state != automatic terminal state for every remediation object`

本轮不建立一般性的 optimal reread interval, 不证明所有 dynamic sources 都必须全量重抓, 也不声称 OpenAI refund process 未完成.

## AGI-scale relevance boundary

长期自主 Agent 的风险不只来自错误 source, 也来自正确 source 在 deliberation 期间过期.

本轮只证明一个 bounded epistemic requirement: 对 action-relevant dynamic proposition, observation-time evidence 与 execution-time truth需要可区分; 当 canonical object 已发生 material transition 时, current judgment 需要 rebind.

这不是 AGI capability claim, 也不证明任何现有 Agent 已实现可靠 temporal rebinding.
