## 研究摘要

Google DeepMind 当前 Gemini 3.8 Flash 产品页继续展示 `Vals Finance Agent v2` 61.4%, 并把该结果用于当前模型性能展示

Vals AI 当前 Finance Agent v2 benchmark-owner 页面标记 `Updated 9/4/2026`, Version 2

Vals 当前 Key Takeaways 直接写明 Muse Spark 1.2 以 60.60% Partial Credit 领先, 且是当前页面唯一高于 60% 的模型

Vals 当前页同时公开 benchmark methodology: 所有 agent 使用共享 default harness 与六个工具, 每题两小时时限, Partial Credit 为主指标, 每个模型运行三次并报告 mean-of-runs 与 standard error, 当前页面报告结果仅基于保持私有的 450-question Test set

这形成两个独立发布者的相关长上下文, 但没有形成可直接核验的同一运行或 correction relation

因此本轮不选择 61.4% 或 60.60% 作为另一个页面的替代事实, 也不把差异写成 Gemini 3.8 Flash 回退

本轮直接执行 P-05 核心变化: 删除发布者身份, 删除快照时间, 删除 benchmark-owner methodology, 并注入把两个页面压成一个 current leaderboard 的冲突摘要

## 研究问题

当 Google provider product snapshot 与 Vals benchmark-owner current snapshot 同时出现 `Finance Agent v2` 名称, 但其当前数值叙述不能直接拼成同一 execution snapshot 时, 是否能保持 publisher, snapshot, score identity 与 methodology 分离

删除 publisher identity, snapshot update 或 Vals methodology 后, 是否会被相同 benchmark 名称诱导成无依据的 correction, regression 或统一 current ranking

## 可证伪假设

- 支持条件: 完整材料保持 Google 61.4% 与 Vals 9/4 current leaderboard 的发布者和快照身份, 删除关键身份后判断相应收窄, 不从相同 benchmark 名称补出同一运行或 correction relation
- 推翻条件: 接受 `Vals 已纠正 Google`, `Gemini 3.8 Flash 从 61.4% 回退`, `Google 61.4% 仍是 Vals 9/4 current leaderboard 第一名` 中任一没有直接关系证据的摘要

## 反例检查

- 相同 `Finance Agent v2` 名称不能证明两个发布者页面展示的是同一 evaluation execution snapshot
- E2 9/4 当前页说 Muse Spark 1.2 是唯一 Partial Credit 高于 60% 的模型, 这与 E1 当前展示 Gemini 3.8 Flash 61.4% 形成需要保留来源身份的页面差异, 但不是自动 correction relation
- E2 当前正文没有 `61.4`, 不能据此推断 Vals 已明确删除, 撤回或纠正 Google 的数值
- 反向也不能用 E1 的 61.4% 覆盖 E2 current benchmark-owner leaderboard
- shared two-hour wall-clock limit 不等于跨 provider identical reasoning effort, token budget 或 hidden inference configuration
- private Test set 保持 benchmark integrity, 但本轮不能独立读取底层 450 test questions 来重放 Google 或 Vals scores
- 本轮没有运行 benchmark, 因此任何正式页面结果都不是本轮 runtime observation

## 暂时结论

Vals 9/4 benchmark-owner current page 与 Google DeepMind current Gemini 3.8 Flash product page 都是可核验的公开来源

它们对 `Finance Agent v2` 的当前展示不能在缺少 same-run, snapshot chronology 与 explicit correction relation 时被压缩成单一 current score

Vals 页面已经补上 P-05 长期欠缺的一部分严格比较条件: benchmark Version 2, shared default harness, six tools, two-hour time limit, explicit scoring, three-run mean aggregation 与 private Test-set boundary

但同一模型的 provider inference configuration 与 Google 61.4% 对应 execution identity 当前仍无法核验

因此本轮支持“benchmark owner / provider snapshot / methodology identity 不能被长上下文合并”, 但不支持模型回退, 官方纠错或统一 current ranking
