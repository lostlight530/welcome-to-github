## 研究摘要

Railway Status 的 2026-03-09 `Deployments stuck` 事件记录, Investigating 阶段说明 new builds 可能 stuck, fail to complete 或 progress slowly, 同时 existing running services are not affected

同一事件随后明确写明 Hobby, free and trial deploys have been temporarily disabled, 后续 Resolved 更新明确 new deployments for free, trial and hobby have been re-enabled

Railway Docs 当前 Free Trial 页面显示 Full Trial 与 Limited Trial 的 `Deploy Code` 均可用, 同时 Limited Trial 保留 network restrictions

因此本轮能够直接核验一个新的发布者中 disable→re-enable 的同对象状态链与当前事件终态, 但不能把历史 incident recovery 或当前 Trial contract 改写为本轮逐项目 runtime success

这直接执行 P-04 的旧状态与较新状态时间替换核心变化, 并满足 2026-09-07 后续优先要求中的新发布者 bidirectional disable→enable 与 current terminal state 条件

## 研究问题

当 Railway 同一正式事件先记录 Hobby, free and trial deploys temporarily disabled, 后记录 new deployments for free, trial and hobby re-enabled 且事件 Resolved 时, 是否应把当前事件判断更新为 deployment restriction lifted / Resolved, 同时保留临时禁用曾发生的历史事实

删除 terminal update, 页面时间或 deployment scope 后, 是否会补出永久禁用, 全计划影响, 逐项目成功或当前 Trial runtime

## 可证伪假设

- 支持条件: 完整材料下保留 2026-03-09 temporary disable 为历史状态, 采用较新的 re-enabled / Resolved 作为该事件当前终态, current Free Trial `Deploy Code` 只承担当前产品契约, 不替代 incident runtime 或逐项目结果
- 推翻条件: 把 temporary disable 改写为永久禁用, 把 re-enabled 改写为每个具体项目 deployment 已成功, 把 Hobby/free/trial 扩大为所有 plans, 删除时间后补回精确时间, 或把 current Free Trial 文档倒写为事件期间运行样本
