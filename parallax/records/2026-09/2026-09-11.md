## 研究摘要

2026-09-10 P-05 已确认 DeepSWE v1.1 使用统一 mini-swe-agent, Google 又明确 Gemini 3.8 Flash 的 73.7% 为 self computed 并使用 high thinking, 但 Datacurve leaderboard display 本身不足以证明 benchmark owner 独立执行该 Gemini row

本轮新增核验 Datacurve 的 current data surface 与 changelog, 当前 leaderboard 仍显示 DeepSWE v1.1 共 113 tasks, `gemini-3.8-flash[high]` 为 74%±1%, 并说明所有模型统一使用 mini-swe-agent

Datacurve data browser 明确将其数据面描述为 DeepSWE 中每个 `(task, model)` rollout 的 outcome, 因此相比单一 leaderboard display 提供了更接近 run-level 的公开核验入口

同时 changelog 在 2026-09-01 对 Gemini 3.8 Flash 使用 `Added Gemini 3.8 Flash results`, 而在 2026-08-13 对 Gemini 3.1 Pro, Gemini 3.5 Flash 与 Gemini 3.6 Flash 明确使用 `Re-ran`, 并说明原因是 LiteLLM token double-counting

因此 public rollout data surface 与 dated model-result addition 可以提高 execution provenance 的可核验程度, 但不能仅凭界面存在和 `Added results` 语义补出 `Datacurve independently re-ran Gemini 3.8 Flash`

本轮直接执行 P-05 核心变化, 删除 rollout data surface, 删除历史 `self computed` qualifier, 再构造 changelog 语义替换和跨快照 provenance 注入, 检查长上下文是否会自动补全独立执行关系

## 研究问题

当 benchmark owner 同时公开 current leaderboard, dated changelog 与 every-rollout data browser 时, 是否足以把 provider self-computed result 升级为 benchmark-owner independent execution

删除 rollout-level 支持, 删除 provider `self computed` 限定, 或把 `Added results` 替换为 `Re-ran independently` 后, 是否会出现无直接证据的 execution provenance 补全

## 可证伪假设

- 支持条件: 完整材料只把 independent execution provenance 更新为部分满足, 保留 benchmark-owner rollout data surface 与具体 Gemini run identity 之间的缺口; 删除关键支持或 provenance qualifier 后判断相应收窄
- 推翻条件: 接受 `Added Gemini 3.8 Flash results` 等于 `Datacurve independently re-ran Gemini 3.8 Flash`, 或仅因 data browser 声明覆盖 every rollout 就声称本轮已取得 Gemini-specific independent run provenance

## 历史背景

2026-09-09 P-05 在 Terminal-Bench 2.1 / StateM 中取得明确 model, effort, agent 与 raw submission identity, 但 custom harness 与 pending adjudication 阻止其成为 cross-provider shared-harness independent result

2026-09-10 P-05 换用 DeepSWE v1.1, 已确认 Datacurve 统一 mini-swe-agent contract 与 Google Gemini 3.8 Flash high-thinking configuration, 但 Google 正式 methodology 将该 Gemini result 明确标为 self computed

因此今天只复验昨日留下的 execution independence 缺口, 不重复把 shared harness 或 high-thinking configuration 当作新完成条件
