## 研究摘要

本日研究一个常见 observability shortcut: 只要 Agent run 有 trace，是否就足以证明后续 auditor 能恢复形成判断所需的完整 evidence lineage.

OpenAI current Agents SDK contract 允许 trace/span 继续存在但省略 sensitive LLM/tool inputs and outputs. Google agents-cli current observability contract 又明确把 Cloud Trace 与 prompt-response logging 分成两个独立 tiers，并存在 trace enabled / no content / prompt-response logging off 的正常环境.

因此本轮得到 bounded result: trace presence 是 execution observability signal，但不是 full evidence recoverability 的充分证明.

## 研究问题

当 Agent execution 已产生 trace 或 spans 时，trace presence 本身是否足以证明后续 auditor 能恢复 LLM message content, tool inputs/outputs 与支撑最终判断的 primary evidence lineage?

## 可证伪假设

- 支持条件: 当前官方合同允许 trace/span 存在，但 message/tool payload 被明确省略、redact 或由独立 logging tier 控制
- 推翻条件: 当前官方合同保证任何 trace presence 都必然无条件包含完整 LLM inputs/outputs, tool inputs/outputs 与 primary evidence lineage，且不存在独立 content-logging policy

## 实验设计

### Trial A

- 目的: 测试 trace/span presence 是否要求 LLM/tool payload 同时存在
- 保持条件: OpenAI Agents SDK tracing surface
- 改变条件: trace_include_sensitive_data true 对比 false
- 预期支持结果: spans continue to exist while sensitive inputs/outputs are omitted
- 预期反证结果: disabling payload capture also eliminates the trace/span itself

### Trial B

- 目的: 测试 execution occurrence 是否要求 tracing surface 必然存在
- 保持条件: OpenAI Agent run contract
- 改变条件: tracing enabled 对比 tracing disabled / ZDR unavailable
- 预期支持结果: tracing can be absent as a configured or policy-constrained observability layer
- 预期反证结果: every run necessarily produces an unavoidable durable trace

### Trial C

- 目的: 跨 publisher 测试 distributed trace 与 full prompt-response evidence 是否是同一个 storage/capture tier
- 保持条件: Google agents-cli agent deployment observability
- 改变条件: Cloud Trace content capture and prompt-response logging configuration
- 预期支持结果: trace can remain enabled with no content while full prompt-response logging is independently off or on
- 预期反证结果: any Cloud Trace presence automatically implies full prompt-response content is stored

## 原始观测

1. OpenAI current tracing documentation states tracing is enabled by default but can be disabled globally or per run, and is unavailable for ZDR organizations.
2. OpenAI current sensitive-data contract states generation/function spans may omit LLM and tool inputs/outputs when trace_include_sensitive_data is false.
3. For official OpenAI endpoints, a redacted Responses span can still retain response_id correlation metadata while request input and response output are omitted.
4. Google agents-cli current observability docs explicitly describe Cloud Trace and prompt-response logging as two independent tiers.
5. Google documents default trace message-content capture as NO_CONTENT and lists local playground plus bare deploy states where Cloud Trace is enabled with no content while prompt-response logging is off.
6. This run did not execute either framework and did not retrieve a concrete trace bundle, GCS JSONL object, BigQuery completion row or application-owned evidence ledger.

## 反例检查

最强反例是应用可以在 trace 之外维护独立 durable evidence ledger，并用 trace_id, response_id 或业务对象 ID 关联原始 source/tool artifacts. 在这种设计中，redacted trace 仍可能足以作为 correlation spine，而完整 evidence 可从另一存储恢复.

Google current docs 本身提供了相邻反例: Cloud Trace 默认可无 content，但 Terraform-provisioned deployments 可以同时开启独立 GCS/BigQuery prompt-response logging. 因此本轮不能写成 "trace redaction necessarily destroys recoverability".

OpenAI 也允许 custom trace processors/exporters, 所以 trace payload 的默认边界不能推广为所有 application-owned provenance architecture.

因此当前结论只能是: trace presence alone is insufficient evidence of recoverability. End-to-end recoverability remains application- and storage-contract dependent.
