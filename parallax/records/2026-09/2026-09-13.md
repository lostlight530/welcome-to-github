## 研究摘要

Integration Bench rev 01 当前公开页把 leaderboard 明确限定为 public development-set numbers, 公开 50 tasks, 20 models 与 1000 published attempts, 每个 model-task cell 只有 one official attempt

同一页面把 public tasks 定义为 development 用途, 把 held-out tasks 定义为 exam, 并明确 capability claims 等待 held-out set

当前 leaderboard 还直接展示不同模型族使用不同 harness, 例如 GPT-5.6 Sol 使用 Codex CLI, Claude Fable 系列使用 Claude Code, 其他多种模型使用 OpenCode

因此本轮可以直接检验两个关键缺失条件: 删除 development-set / held-out 身份后是否会把当前公开分数扩大成一般能力结论, 删除 harness 身份后是否会把 cross-model ranking 改写成 identical-harness model-only comparison

公开数据 manifest 进一步固定 rev 01 preliminary, 50 public tasks, 1000 attempts 与 scorer identity, 并为 GPT-5.6 Sol 记录 Codex harness 与 xhigh reasoning identity

这些材料提供 per-benchmark methodology 与公开 run provenance 表面, 但没有提供已完成的 held-out capability sweep, 因此当前研究只形成有边界的 development-set observation

## 研究问题

当 benchmark owner 同时公开 development-set identity, held-out boundary, one-official-attempt contract, scorer 与 family-specific harness 时, 是否能够保留当前 public sweep 的可核验结果, 同时拒绝把公开 leaderboard 扩大为 held-out capability claim 或 identical-harness model-only comparison

删除 development-set 或 harness identity 后, 是否会从剩余的 rank, score, model name 与 published-run metadata 中自动补回缺失条件

## 可证伪假设

- 支持条件: 完整基线只支持 rev 01 public development-set result; 删除 development-set / held-out identity 后 capability/generalization 判断收窄; 删除 harness identity 后拒绝 identical-harness 解释; 注入 current rank 已证明 held-out general capability 的摘要时保持拒绝
- 推翻条件: 在缺少 development-set identity 时仍把 public score 写成 held-out capability, 在缺少 harness identity 时仍声称所有模型运行条件相同, 或把 one official attempt per cell 与 expected rerun interval 改写为已经完成多次独立复现
