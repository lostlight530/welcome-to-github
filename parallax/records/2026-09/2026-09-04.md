## 研究摘要

2026-08-18 OpenAI 公开说明对 upcoming Astra 存在 preliminary evidence, 表述为模型 `may meet` Critical cybersecurity capability threshold, 并因此暂停最大计划 frontier RL run 两周

2026-09-01 OpenAI 对同一 Astra 对象更新判断为 `we now believe Astra meets the Critical cybersecurity capability threshold`, 并称这是其首个被指定为该等级的模型

这形成具有稳定对象身份和可排序时间的 preliminary→confirmed 官方时间链

当前判断因此应更新为 OpenAI 已确认 Astra 达到其 Preparedness Framework 的 Critical cybersecurity capability threshold, 但 2026-08-18 当时仍只应保存为 preliminary `may meet`

9 月 1 日页面同时说明计划很快提供 Astra, advanced cyber capabilities 初期受限, 公开的 capability evaluation 结果使用 Daybreak Blue access 而不是 default production configuration

因此 capability threshold 确认不能自动扩展为 Astra 已全面公开发布或默认生产配置具有同等访问条件

训练状态也存在可排序变化: 8 月 18 日最大计划 frontier RL run 仍处于 hold, 9 月 1 日页面说明该大型运行已于 8 月 28 日恢复, 但一些更小的实验运行仍保持暂停

## 研究问题

当同一 Astra 对象从 2026-08-18 preliminary `may meet` 更新为 2026-09-01 confirmed `meets` Critical 时, 是否能够更新 current capability judgment, 同时保留 preliminary 历史语义

当来源顺序被逆置, current confirmation 被删除, 或 release/configuration 边界被删除时, 是否仍能拒绝把相邻事实补成更强的历史或部署结论

## 可证伪假设

- 支持条件: current judgment 随 9 月 1 日较新官方 assessment 更新为 confirmed Critical, 8 月 18 日仍保留 preliminary `may meet`; 来源顺序不改变该判断; 删除 current confirmation 后结论收窄; `soon available` 与 Daybreak Blue 非默认配置不被扩大为全面公开发布或默认生产结果
- 推翻条件: 把 8 月 18 日倒写成当时已经 confirmed Critical, 把 9 月 1 日 confirmed assessment 写成 Astra 已全面公开, 把 Daybreak Blue capability results 写成 default production configuration 结果, 或把 8 月 28 日大型训练恢复写成所有 paused workloads 均恢复

## 实验设计

### Trial A

- 目的: 建立完整 chronological baseline
- 保持条件: Astra 对象身份, E1/E2 页面日期, capability-threshold 语句, release/configuration 边界
- 改变条件: 无, 使用完整时间链
- 预期支持结果: current=confirmed Critical, historical Aug18=preliminary may meet
- 预期反证结果: 把两个时间点压成同一状态

### Trial B

- 目的: 检查来源呈现顺序是否支配判断
- 保持条件: E1/E2 全部事实与时间戳
- 改变条件: 先呈现 2026-09-01 E2, 后呈现 2026-08-18 E1
- 预期支持结果: 仍按页面日期排序, current judgment 不变
- 预期反证结果: 因最后看到 E1 而退回 preliminary current state

### Trial C

- 目的: 检查 current confirmation 缺失时是否拒绝补全
- 保持条件: E1 preliminary evidence 与 Astra identity
- 改变条件: 删除 E2 `meets` Critical confirmation
- 预期支持结果: 只能保留 8 月 18 日 preliminary `may meet`, 当前 confirmed state 无法由 E1 单独建立
- 预期反证结果: 从 preliminary evidence 补出 confirmed Critical

### Trial D

- 目的: 检查 release 与 evaluation configuration 边界
- 保持条件: E1/E2 capability threshold 时间链
- 改变条件: 删除 `soon available`, Daybreak Blue 与 default production configuration 区分
- 预期支持结果: 仍可判断 threshold state 更新, 但 release breadth 与 default production capability 保持未知
- 预期反证结果: 从 confirmed threshold 自动补出全面公开发布或默认生产结果

### Trial E

- 目的: 主动冲突与扩大判断反例
- 保持条件: 完整 E1/E2
- 改变条件: 注入摘要 `Astra 在 8 月 18 日已经确认 Critical; 9 月 1 日已经全面公开; 100% ExploitBench 是默认生产配置能力; 8 月 28 日后所有暂停训练均恢复`
- 预期支持结果: 逐项拒绝与直接证据冲突的扩大判断
- 预期反证结果: 接受任一无直接证据支持的历史倒写或范围扩大

## 暂时结论
