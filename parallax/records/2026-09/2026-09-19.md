## 研究摘要

Parallax 2026-09-17 frontier 把 delegated evidence chain 定义为下一阶段优先问题: 多 Agent、tool、retrieval layer 与 summarizer 共同形成判断时, primary evidence、delegation identity、attribution 与 source independence 是否仍可恢复.

本轮第一次把该 frontier 变成 Daily research batch, 但不因此创建新 CASE 或 NOTES finding.

Anthropic 的公开 Research 架构给出一条真实 production multi-agent evidence path: lead agent 制定计划并创建并行 subagents; subagents 搜索并把 findings 返回 lead; lead 汇总后把 findings 交给独立 CitationAgent 定位 citation. 同一文章还明确提出 `Subagent output to a filesystem to minimize the game of telephone`: 对某些结果让 subagent 直接写持久 artifact, 只把轻量 reference 返回 coordinator, 以减少多阶段传递中的信息损失.

Google ADK 当前文档给出另一种独立 framework contract: `sub_agents` 建立 agent hierarchy; LLM-driven delegation 通过 `transfer_to_agent(agent_name=...)` 改变 execution focus; workflow agents 可以共享 InvocationContext/state 传递结果. 这些字段直接描述 delegation target、control flow 与 state transport, 但当前所读 contract 并没有因此自动建立任意外部事实的 primary-source identity、publisher independence 或 citation lineage.

因此本轮研究的窄问题不是 `multi-agent 好不好`, 而是: 当 delegation/handoff 本身完全可定位时, 是否可以把 `谁执行了哪一段` 自动当成 `这段结论来自哪个 primary evidence`.

## 研究问题

在多 Agent 研究链中, 如果 coordinator→subagent 的 delegation target、agent hierarchy、shared state 或 handoff 都可定位, 这些 orchestration metadata 是否足以自动证明最终 claim 的 primary-source provenance 与 source independence; 还是必须另外保留 source/artifact identity

## 可证伪假设

- 支持条件: E1/E2 都允许明确识别 agent/control-flow relation, 但只有显式 citation stage、source reference 或独立 artifact path 才承担 claim→evidence attribution; 删除 source/artifact identity 后应停止声称 primary provenance 已恢复
- 推翻条件: 当前直接文档明确规定 delegation/handoff metadata 本身完整携带并可恢复每个 downstream claim 的 primary source identity、publisher relation 与 source independence, 即使 source reference/artifact identity 被删除

## Identity boundary

本轮必须分开:

- agent identity: lead/coordinator/subagent/CitationAgent
- delegation identity: 谁把控制或任务交给谁
- execution focus: 当前由哪个 agent 执行
- state transport identity: 哪些内容通过 shared context/state/return value 传递
- evidence artifact identity: 原始网页、文档、文件或持久 artifact
- publisher identity: evidence artifact 的发布者
- claim-support relation: 哪个 artifact 直接支持哪个 claim
- citation identity: 最终输出中指向哪个 source location
- source independence: 多个 source 是否来自独立 evidence chain

`known delegation path != known evidence provenance`

`shared state != primary-source lineage`

`subagent identity != publisher identity`

`citation stage exists != every upstream claim was independently verified`

## 实验设计

### Trial A｜完整 provenance baseline

- 目的: 建立 E1 中 agent chain 与 citation/artifact chain 同时存在时的结构基线
- 保持条件: lead→subagent→lead→CitationAgent 关系、documents、research report、citation stage、filesystem artifact recommendation 全部保留
- 改变条件: 无
- 预期支持结果: agent/control-flow identity 与 evidence/citation identity 可同时描述但承担不同职责
- 预期反证结果: E1 明确把 delegation identity 定义为足以替代 source/citation identity

### Trial B｜删除 primary source/artifact identity

- 目的: 测试 known subagent identity 是否足以恢复 source provenance
- 保持条件: `Subagent A` 完成搜索并向 lead 返回 finding F, delegation path 完整
- 改变条件: 删除 F 的 URL/document/artifact/publisher reference
- 预期支持结果: 可以知道 F 来自 Subagent A 的输出, 但不能据此知道 F 的 primary publisher/source independence; provenance 收窄为 agent-output provenance
- 预期反证结果: 仅凭 Subagent A 身份即可唯一恢复其使用的 primary evidence

### Trial C｜same-publisher fanout counterexample

- 目的: 检查多个 subagents 是否会被误计为多个独立 source
- 保持条件: 三个 subagents、三个独立 delegation branches
- 改变条件: 三个 subagents 都只读取同一 publisher 的同一 primary artifact
- 预期支持结果: execution branches = 3, independent primary evidence chain 仍最多 = 1
- 预期反证结果: agent 数量本身合法增加 source independence

### Trial D｜CitationAgent 反例

- 目的: 检查 final citation stage 是否自动证明 upstream independent verification
- 保持条件: E1 的 CitationAgent role
- 改变条件: 假设 upstream lead/subagents 已经产生一个 unsupported claim, 但 CitationAgent 只负责从 documents/report 定位 citation
- 预期支持结果: citation-stage existence 不能自动证明 upstream claim 已被独立复现; 必须检查 citation 是否实际支持 claim
- 预期反证结果: E1 直接规定 CitationAgent 对每个 claim 执行独立 factual reproduction

### Trial E｜Google ADK delegation contract cross-check

- 目的: 检查独立 framework 中 handoff metadata 是否等于 evidence metadata
- 保持条件: coordinator、target subagent、`transfer_to_agent`、agent hierarchy/state contract
- 改变条件: 删除外部 source references, 只保留 transfer target 与 state/result
- 预期支持结果: ADK contract 仍能描述 control flow, 但不能从 transfer target 自动恢复外部 source publisher/citation lineage
- 预期反证结果: current ADK contract 明确使 transfer metadata 成为完整 external-evidence provenance record

### Trial F｜direct artifact bypass counterexample

- 目的: 尝试推翻 `所有 multi-agent compression 都必然丢 provenance`
- 保持条件: E1 subagent research task
- 改变条件: 使用 E1 明确提出的 direct filesystem artifact + lightweight reference path, 而不是让所有内容经 coordinator 重述
- 预期支持结果: provenance loss 不是 multi-agent 的必然属性; 显式 artifact/reference channel 可以减少多阶段转述损失
- 预期反证结果: E1 没有提出任何绕过 coordinator compression 的持久 artifact 机制

## 原始观测

- Trial A: E1 将 research execution chain 与 CitationAgent/citation processing 分成不同阶段; 说明 orchestration 与 attribution 在架构上不是同一字段
- Trial B: 当前公开材料没有规则允许从 `哪个 subagent 说了 F` 唯一推出 `F 来自哪个 primary publisher`; 删除 source/artifact reference 后只剩 agent-output provenance
- Trial C: 多 subagent branch 可以在 execution 上独立, 但如果输入来自同一 publisher/artifact, Parallax 的 source independence 计数不增加
- Trial D: E1 说明 CitationAgent 根据 documents 与 research report 定位 specific locations for citations; 当前文本不足以把该步骤扩大为对每个 upstream claim 的 independent runtime reproduction
- Trial E: E2 直接描述 transfer target、hierarchy 与 execution focus; 当前所读 contract 没有把这些 orchestration fields 定义为外部网页/报告的 publisher/citation lineage
- Trial F: E1 明确建议 specialized subagent 可以把输出持久化到 filesystem, 只把 lightweight references 交给 coordinator, 目的之一是减少 `game of telephone` 与多阶段复制的信息损失

以上是本轮对公开材料的直接读取与受控字段删除结果, 不是 Claude Research 或 ADK runtime trace.

## 反例检查

首选解释如果写成 `multi-agent delegation 会天然丢失 provenance`, E1 自己就提供反例: direct subagent artifact + lightweight reference 可以绕过 coordinator 的重复转述并减少 `game of telephone`.

因此本轮不形成 `multi-agent 必然导致 provenance loss` 的结论.

另一个反例是 `CitationAgent 存在所以 provenance 已解决`. E1 只足以证明系统具有专门 citation processing stage; 本轮没有 CitationAgent 的 raw trace、错误率或 independent factual replay, 因而不能把 architecture existence 升级为 perfect attribution guarantee.

Google ADK 则反驳另一种混并: framework 可以明确知道 transfer target 与 execution focus, 但这与 claim 的 external source identity 是不同层级的问题.

## 暂时结论

**观察**.

在本轮两个独立发布者的公开架构/合同中, delegation identity 与 evidence provenance 必须分开建模.

Anthropic production description 直接展示了 lead/subagent/citation stages 的分工, 并明确提出 direct artifact/reference path 来减少多阶段转述损失. Google ADK 独立展示 delegation target、hierarchy 与 state/control-flow metadata 可以被显式建模.

当前最窄、可支持的判断是:

> 已知 `哪个 Agent 接手了任务` 或 `哪个 Agent 返回了结果` 不足以自动建立该结果的 primary-source identity、publisher independence 或 claim-specific citation support; 这些 evidence coordinates 需要显式 source/artifact/citation metadata 或可定位 trace.

但本轮没有 runtime replay, 所以不声称 Anthropic/ADK 在实际运行中发生了具体 provenance loss, 也不声称某种 artifact design 已经量化消除了该问题.

## AGI-scale relevance boundary

长期无人值守 Agent 如果通过多 Agent、retrieval tool 与 summarizer 分层压缩证据, 只记录 agent handoff 而不记录 evidence lineage, 后续系统可能知道 `谁说了什么` 却不知道 `什么直接支持它`.

本轮只研究这种 epistemic property 的身份边界, 不构成任何 AGI capability claim.
