## 研究摘要

同一个 session ID 不是 durable state recovery 的充分证明，当前官方合同都把 identity 与 storage/runtime lifetime 分开

## 研究问题

相同 session identifier 是否足以证明 conversation history 与 execution state 在下一次运行仍可恢复

## 可证伪假设

若相同 session identity 在不同 backend 或 runtime lifetime 下具有不同 persistence behavior，则假设成立；若 ID 本身保证全部状态恢复，则被推翻

## 历史背景

## 原始观测

OpenAI Session 在 run 前读取 history、run 后写入新 items，并要求恢复时保持同一底层 storage；SQLiteSession 默认内存存储随 process 结束而丢失，文件存储可持久化

Google agents-cli 明确 local session 位于 running server memory，保持 server 存活才可跨 separate runs resume

本轮没有执行 framework runtime 或 restart test
