## 研究摘要

本日研究 handoff 成功转移 control 或 task ownership 时，是否可以把该事件直接当成完整 evidence/execution provenance 已同步给接收 Agent 或后续 auditor 的证明.

当前 OpenAI Agents SDK 与 Microsoft Agent Framework 的公开合同都允许 handoff 与 forwarded-context / tracing surface 分离. 因此本轮得到一个 bounded observation: control transfer identity, task ownership identity, forwarded context identity 与 durable execution provenance identity 不能自动坍缩为同一事实.

## 研究问题

当 Agent A 成功 handoff 给 Agent B 时，handoff 成功本身是否足以证明 B 或后续审计者拥有 A 在 handoff 前形成判断所需的完整 tool-call, tool-result, evidence lineage 与 execution trace provenance?

## 可证伪假设

- 支持条件: 至少一个当前官方框架合同允许 handoff 成功而 forwarded history, tool-control content, session state 或 trace availability 发生过滤、分离或关闭
- 推翻条件: 当前官方合同保证每次 handoff 都无条件、不可配置地把全部 tool calls, tool results, evidence lineage, session state 与 durable trace 完整传递并保留给接收方和后续 auditor

## 历史背景

2026-09-19 Daily 首次研究 delegated evidence chain，结论边界是 delegation/execution provenance 不等于 evidence provenance，agent count 不等于 source independence.

本轮不重复该抽象结论，而把对象缩小为 handoff lifecycle 本身，直接测试 control ownership, forwarded conversation, tool-control artifacts 与 trace persistence 是否具有相同 identity.

2026-09-24 Daily 研究的是 action-time tool capability freshness. 本轮不改变 tool inventory，而研究已经发生 handoff 后哪些执行/证据对象被传递或留下可审计痕迹.

## 实验设计

### Trial A

- 目的: 测试 control transfer 是否要求 forwarded history 保持固定且完整
- 保持条件: OpenAI Agents SDK handoff object 与同一 receiving agent
- 改变条件: default forwarding 对比显式 input_filter / remove_all_tools 路径
- 预期支持结果: handoff 仍可发生，但接收 Agent 所见 structured tool-related history 可变化或被移除
- 预期反证结果: handoff 只要成功，接收 Agent 必然得到不可过滤的完整 prior execution history

### Trial B

- 目的: 测试 handoff occurrence 是否等于 durable trace evidence 必然存在
- 保持条件: OpenAI handoff lifecycle
- 改变条件: tracing enabled 对比 tracing disabled / unavailable condition
- 预期支持结果: handoff 是独立 execution event，但 trace recording availability 受配置或数据保留条件约束
- 预期反证结果: handoff 一旦发生就无条件产生不可关闭且后续可取的 durable trace

### Trial C

- 目的: 跨 publisher 测试 task ownership transfer 是否等于完整 tool/execution context transfer
- 保持条件: Microsoft Handoff orchestration 与 same task transition
- 改变条件: synchronized user/agent message surface 对比 tool-related/control content surface
- 预期支持结果: receiving agent 可取得 task ownership，同时 session identity 分离且部分 tool-control content 不被广播
- 预期反证结果: full task ownership 在合同上要求所有 session/tool-control content 原样共享

## 原始观测

1. OpenAI 当前 Handoffs 文档将 handoff 表示为 tool，并明确 helper 会把 control 转移到指定 Agent.
2. 同一文档允许 input_filter 改变 receiving agent 获得的 input，官方 remove_all_tools helper 可以移除 structured tool-related items.
3. OpenAI 当前 Tracing 文档将 handoff 单独记录为 handoff_span，但 tracing 可以通过配置关闭；ZDR organization 下 tracing 不可用.
4. Microsoft 当前 Handoff 文档明确区分 control flow 与 task ownership，receiving agent 在 handoff 后取得 full ownership.
5. Microsoft 同页同时说明参与 Agent 不共享同一个 AgentSession；同步的是 user/agent messages，tool related contents including handoff calls 不广播，Python 路径还会在 forwarding 前过滤 function calls, function results, approval payloads 与其他 tool-control content.
6. 本轮没有运行 OpenAI Agents SDK 或 Microsoft Agent Framework，没有取得 production trace, session dump, tool-call ledger 或 semantic outcome.

## 反例检查

首选解释可能被反例 "handoff full context means complete provenance is always transferred" 推翻.

Microsoft 文档确实使用 full context / full task ownership 语言，但同一 current contract 又明确说明 Agents 不共享同一 session，tool-related contents 不广播，并在 Python forwarding path 过滤 function calls/results 等 tool-control content. 因而 conversation/task continuity 不能自动解释为 complete execution provenance continuity.

另一个反例是 "OpenAI 默认 tracing 已记录 handoff，因此 provenance completeness 已自动解决". 当前合同只证明 handoff_span 属于默认 tracing surface. tracing 可以关闭或因 ZDR unavailable；同时 receiving history 还能通过 input_filter 改写. 所以 trace visibility 与 receiving-agent evidence context 仍是两个 identity.

本轮没有直接 runtime，因此不能判断具体 host 是否真正出现 provenance loss，也不能量化其对最终 semantic outcome 的影响.

## 暂时结论

当前状态保持观察.

在本轮直接核验的两个独立 publisher 合同中，handoff control/task ownership transfer 不能作为 complete evidence/execution provenance transfer 的充分证明.

对长期 Agent 系统，至少需要分别记录 handoff event identity, sender/receiver identity, forwarded-history policy, session identity, tool-call/result provenance, trace availability 与 evidence lineage. 缺少其中关键字段时，应保持 PARTIAL 或 UNKNOWN，而不是从 "handoff succeeded" 自动补全.

## AGI-scale relevance boundary

长期自主 Agent 可能跨多个 specialist, session 与 execution surface 转移 task ownership. 如果系统把 control transition 当成 provenance continuity，后续 Agent 可以拥有正确任务上下文，却缺少支撑原判断的 tool/evidence lineage，审计者也可能只看到路由成功而无法重建执行链.

本轮只研究 epistemic provenance contract，不构成任何模型能力或 AGI capability 声明.
