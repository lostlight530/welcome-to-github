## 研究摘要

本日研究 workspace 声明与真实执行权限之间的跨层 identity: 客户端向 MCP server 提供一组 roots, 或 Agent sandbox 声明初始 workspace manifest, 是否足以证明进程无法访问列表外的文件, 以及当前 live workspace 与初始声明完全相同

MCP 2025-11-25 Roots 文档要求支持该能力的 client 声明 roots capability, 通过 roots/list 暴露 file URI, 并将适当权限、URI 校验、access control 与 root 边界检查列为安全要求或建议. MCP Python SDK v2 当前文档直接澄清 roots 是 informational guidance, not an access-control mechanism

MCP 2026-07-28 已将 roots 标为 deprecated, 但仍处于兼容期, 不能把 deprecated 改写为 removed. OpenAI Agents SDK SandboxAgent 文档将 harness control plane 与 sandbox compute plane 分开, 且明确 Manifest 只描述 fresh-session 起始内容, 复用 live session 或 snapshot 时不能当作每次运行的 live filesystem truth

本轮另外执行一个真实本地临时文件系统对照: 在无独立 OS sandbox policy 的 Python 进程中声明 workspace 目录, 直接读取目录外自建测试文件仍成功; 目录内 symlink 与同名前缀 sibling 路径能通过 naive textual prefix, 但 canonical containment 将其排除. 该实验不模拟 MCP wire, 不声称突破 OpenAI sandbox, 只验证 path declaration、lexical matching 与 effective execution policy 不是同一事实

当前结论 PARTIAL: 对协议与路径身份边界有直接证据, 对真实隔离强度没有运行证据

## 研究问题

MCP roots/list 的已声明目录集合, 或 SandboxAgent fresh-session Manifest, 能否单独证明当前执行进程的 effective filesystem permissions, 路径访问限制以及恢复后 live workspace 的完整状态

## 可证伪假设

- 支持条件: 官方规范或 SDK 明确把 roots 定位为 informational guidance 而非 enforcement, sandbox 文档将 manifest 与 live session 区分, 在受控本地文件系统中同一 declared root 可以与不同实际读写可达性共存
- 推翻条件: 适用正式合同明确承诺 roots/list 自动实施不可绕过的 OS isolation, Manifest 在所有 resumed session 中都必然是完整实时文件系统事实, 且受控无隔离进程在仅声明 root 后对 root 外自建测试文件的读取必然失败

## 控制条件

固定本地 Python standard-library runtime, 使用单次 tempfile.TemporaryDirectory 创建 workspace, outside 与 workspace-extra 三个测试目录, 所有读取目标均是本轮创建的非敏感 marker 文件

声明的唯一 root 为 workspace. 直接读取由当前 host Python process 执行, 未配置 MCP client/server, 未启用额外 filesystem sandbox, 未更改 OS user identity

比较三个独立变量: textual prefix membership, resolved canonical containment, 以及本地显式 application gate = canonical containment AND synthetic policy flag. Gate 是实验代码逻辑, 不是 OS sandbox

对于 source contract, MCP 2025-11-25 与 2026-07-28 分别保留版本身份, OpenAI living docs 仅记录 2026-10-12 访问时状态

### Trial C: local path identity and access

- 目的: 构造同一 declared root 下的 path alias, textual prefix 和 effective gate 反例
- 保持条件: same root directory, same Python process, temporary self-owned marker files

## 原始观测

1. E1 MCP 2025-11-25 Roots page specifies roots/list and file URI, client MUST expose only appropriately permissioned roots, validate root URIs and implement access controls
2. E1 server SHOULD respect root boundaries and validate paths; normative SHOULD is not proof that any specific server has done so
3. E2 MCP Python SDK v2 says roots are informational guidance, not an access-control mechanism
4. E2 and E3 say roots deprecated at 2026-07-28 and retained for at least twelve months, so deprecated does not mean removed
5. E4 OpenAI Sandbox Agents separates harness ownership of tool routing/approval/tracing from sandbox execution ownership of files/commands/mounts
6. E4 states Manifest describes desired fresh-session starting layout, while reused live sessions or snapshots may determine effective workspace
7. E5 says agent-generated code can access files and network available to its environment, and recommends isolation and restricted credentials
8. Local fixture created workspace/inside.txt, outside/outside.txt, workspace-extra/neighbor.txt and workspace/alias symlink to outside
9. Local case inside_allowed: lexical_inside=true, canonical_inside=true, host_read_succeeded=true, application_gate_allows=true
10. Local case outside_direct: lexical_inside=false, canonical_inside=false, host_read_succeeded=true, application_gate_allows=false
11. Local case symlink_escape: lexical_inside=true, canonical_inside=false, host_read_succeeded=true, application_gate_allows=false
12. Local case sibling_prefix: lexical_inside=true, canonical_inside=false, host_read_succeeded=true, application_gate_allows=false
13. Local case inside_policy_denied: lexical_inside=true, canonical_inside=true, host_read_succeeded=true, application_gate_allows=false
14. Ten executed predicates all true: inside canonical and gate, outside host read and canonical exclusion, symlink lexical inclusion/canonical exclusion/gate exclusion, sibling lexical inclusion/canonical exclusion, inside explicit-policy denial
15. No MCP roots/list request, sandbox mount policy, OS denial trace, provider sandbox resume or privilege escalation was executed

## 反例检查

最强反例是某个具体 MCP host 将 roots 与真实 OS sandbox mount namespace, filesystem ACL 或能力安全机制绑定, 且提供当前进程的拒绝访问证据. 这种实现可以做到根目录之外的有效限制, 但限制来自额外 enforcement, 不是 roots/list 消息本身

另一反例是所有目标都在 canonical root 内且 OS 权限同样限制, 此时 root guidance 与实际访问范围可以偶然一致, 但一致性不能证明是 root 声明自动施加的权限

在 local fixture 中, root/alias 的 lexical prefix 为 true, resolve 后位于 outside; workspace-extra 的字符串也以 workspace 开头. 这推翻 naive prefix 作为安全证明, 但不证明所有 path validation 实现都有同样缺陷

Application gate 是受控布尔逻辑, 不构成抗 TOCTOU、符号链接替换、bind mount 或多用户权限竞争的 production enforcement. 若路径在检查后变化, 仅一次 resolve 也不足以证明后续实际 open 操作安全

OpenAI Manifest 可以与某次 fresh session 的内容一致, 但文档明确允许 live reused session/snapshot 路径, 所以不能无条件推广到所有当前执行
