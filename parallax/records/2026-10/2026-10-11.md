## 研究摘要

今天研究长期 Agent capability registry 的一个容易混淆的关系: 先前成功读取 AgentCard 或 tools/list, 且缓存尚未超过 max-age 或 ttlMs, 是否足以证明当前能力集合仍未变化, 或多页列表必然是同一时点的完整快照

A2A v1.0.1 Section 8.6 建议 Agent Card HTTP endpoint 提供 Cache-Control max-age 与 ETag, 客户端遵循 HTTP cache semantics, 缓存过期后使用 conditional requests, 没有 caching headers 时允许 implementation-specific default

MCP 2026-07-28 Caching 规定 complete tools/list 等结果携带 ttlMs 和 cacheScope, 明确 TTL 是 freshness hint 而非数据不变保证, notification 可在 TTL 未过期时使缓存立即 stale, private cache 不可跨不同 context 复用, paginated list 没有跨页一致性保证

本轮直接执行固定时间轴和五组有限 cache cases, 六项 predicates 均为 true, 证明同一 fresh cache marker 与不同 underlying state 可以共存, notification 和 context identity 影响合法复用, 多页可以来自不同状态版本

结论为 PARTIAL, 因为没有运行真实 HTTP conditional GET, MCP notification delivery, paginated tools/list 或 server mutation

## 研究问题

A2A Agent Card 的 HTTP freshness 与 MCP tools/list 的 ttlMs/cacheScope 能否独立证明 capability registry 的 current-state accuracy, 同一调用方的缓存可复用性, 以及跨页列表的 snapshot completeness

## 可证伪假设

- 支持条件: 正式规范把 TTL 描述为缓存有效性提示而非不变性承诺, 存在主动 invalidation 与分页边界, 合成固定 TTL 内可以发生服务器变更
- 推翻条件: 适用规范明确要求 server 在 TTL 内绝不修改能力数据, 或强制所有分页共享原子 snapshot, 且有限控制中 freshness 与 changed state 不能同时成立

## 实验设计

### Trial A

- 目的: 直接核验 A2A Agent Card 的 HTTP caching 与 conditional refresh 约束
- 保持条件: A2A v1.0.1 Agent Card, same card URL
- 改变条件: max-age/ETag presence and expiry state
- 预期支持结果: SHOULD advertise cache hints, client SHOULD conditional refetch on expiry
- 预期反证结果: cache-validity period 被定义为服务器绝不变更的强制证明
- 执行方式: official E1 contract read; HTTP GET/304 NOT_EXECUTED

### Trial B

- 目的: 核验 MCP complete tools/list 缓存、notification invalidation 与分页一致性
- 保持条件: MCP 2026-07-28 complete list and caching model
- 改变条件: ttlMs, cacheScope, notification and pagination cursor
- 预期支持结果: TTL hint only, private context separation, notification immediate invalidation, no cross-page snapshot guarantee
- 预期反证结果: 所有 fresh cached pages 都由规范保证来自相同 immutable server snapshot
- 执行方式: official E2/E3 contract read; live tools/list NOT_EXECUTED

### Trial C

- 目的: 执行有限 synthetic cache timeline counterexample
- 保持条件: same t_received, TTL and server change/read timestamps
- 改变条件: A no notification, B notification received, C/D private context mismatch/match, E two pages read around state change
- 预期支持结果: fresh while changed, notification invalidation, private context isolation and mixed-page possibility
- 预期反证结果: fresh TTL 强制 server unchanged 或不同 context/private cache 可合法直接复用
- 执行方式: deterministic local JavaScript, five cases and six predicates, no external runtime

## 原始观测

1. E1 A2A Agent Card HTTP endpoints SHOULD include Cache-Control max-age and ETag, MAY include Last-Modified
2. E1 client SHOULD honor HTTP caching, expired card SHOULD use If-None-Match or If-Modified-Since, absent headers MAY use default cache duration
3. E2 MCP complete tools/list result MUST carry caching hints, ttlMs is milliseconds, cacheScope is public/private
4. E2 TTL is freshness hint not guarantee, underlying data MAY change before TTL expires
5. E2 relevant notification received during fresh TTL invalidates cached response immediately
6. E2 private cached response MUST NOT be shared across different authorization contexts, pages are independently cached without cross-page consistency guarantee
7. E3 tools/list MAY change over time and supports pagination; listChanged notification depends on capability and subscription
8. Synthetic fixed input: received=0, ttlMs=300000, changedAt=120000, observedAt=180000, notificationAt=150000
9. Synthetic A: cacheFresh=true, serverChanged=true, notificationReceived=false, stale view possible
10. Synthetic B: cacheFresh=true, serverChanged=true, notificationReceived=true, notification invalidates cache
11. Synthetic C: private scope, originContext=principal-A, requestContext=principal-B, cross-context reuse forbidden
12. Synthetic D: private scope, originContext=principal-A, requestContext=principal-A, same-context reuse eligible subject to freshness
13. Synthetic E: pageOneObservedVersion=1, pageTwoObservedVersion=2, changeBetweenPages=true

## 反例检查

最强反例是某个具体服务将能力数据固定为 immutable versioned snapshot, 且所有分页绑定同一 snapshot version, 这种实现可以提供比基础 cache hint 更强的 current-state or snapshot-consistency evidence, 但本轮没有其实际执行证明

另一个反例是 cache hit 之后没有任何 server change, 此时缓存内容确实可能仍准确, 但一次准确不等于 TTL 在所有情况下都是不可变性证明

MCP private scope 只约束不同 context 的复用, 相同 context 并不自动绕过 TTL, notification 或后续调用验证, 本轮 synthetic D 不证明任何真实工具可调用

Synthetic E 只展示跨页 version mismatch 的结构可能性, 不构成真实 MCP 服务出现 gap 或 duplicate 的观测

## 暂时结论

当前状态为 PARTIAL

```text
CACHE_FRESH
!= SERVER_STATE_VERIFIED_CURRENT
!= CONSISTENT_MULTIPAGE_SNAPSHOT
```

A2A 的 HTTP cache hints 用于高效 Agent Card 获取, MCP 的 TTL/private scope/notification/pagination 合同用于受控缓存复用, 均不应被长期 Agent 当成独立的当前能力执行证明

建议 capability registry 记录 source publisher, protocol version, discovery artifact identity, cache key and scope, received-at, TTL, last revalidation, invalidation event, page cursor and snapshot identity if provided, and actual invocation result
