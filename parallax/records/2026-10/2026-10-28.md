## 研究摘要

本日比较 2026-10-27 UTC 两次已成功 GitHub Pages 部署, 两次 workflow run 使用不同 head commit, Git 比较报告中间有 3 个提交并新增 2 个 Markdown 路径, 但两份本日实际下载的 Pages ZIP 在解包后恰好包含相同的 3 个普通文件路径, 三者对应 SHA256 完全相同, 新增的 2 个 Markdown 源码路径均不在部署包中

两份 ZIP 的 SHA256、大小和内层 TAR digest 均不同, 8 个 TAR 成员的 mtime 均不同, 但这些 archive-level differences 没有形成 regular-file payload byte difference, 因此既不能从 source commit delta 推出 deployed payload delta, 也不能从 deployment success 或 archive hash 推出公共网站当前响应内容, 结论 PARTIAL

## 研究问题

When a repository advances through commits and both GitHub Pages deployments succeed, does a changed source head or changed ZIP digest establish a changed set of deployed regular-file bytes or current public HTTP content

## 可证伪假设

- 支持条件: two successful deploy runs bind different source commits with nonempty source diff, both archived ZIPs are independently obtained and verified, ZIP/TAR digests differ, but extracted regular-file path and SHA256 maps match exactly

- 归因限制: archive metadata can vary without payload bytes varying, unchanged extracted bytes do not prove public Pages current response equality or explain all build causes, two GitHub pages and logs do not count as independent publishers

## 反例检查

The source diff is real and includes two newly added Markdown files, which refutes a trivial explanation that both source commits are identical. Conversely, neither added source file appears among the three extracted regular-file paths, and the three actual deployed archive file digests match exactly, refuting the inference that any source commit delta forces payload-byte delta. Unequal ZIP sizes and SHA256 refute archive identity, but cannot refute regular-file identity. A later public HTTP response with a different body would be a counterexample to extending this bounded artifact conclusion to served content, no such response was observed

## 暂时结论

PARTIAL: the two pinned GitHub Pages deploy jobs succeeded against different source commits and produced different ZIP/TAR archive bytes, yet the locally downloaded archives contain the same three regular files with byte-identical SHA256 hashes. This demonstrates a bounded source-commit versus artifact-payload identity separation in the observed pair. It does not prove the current CDN response, browser behavior, site availability to all clients, deployment retention beyond the access cut, or a general reproducible-build property

## AGI-scale relevance boundary

For long-running Agent systems, source revision, execution receipt, archive digest, normalized output file identity and client-observed effect are separate evidence coordinates. A source change is not a reliable proxy for output change, and a successful tool/deploy receipt is not a substitute for direct client acceptance, this is evidence-chain research rather than an AGI capability claim
