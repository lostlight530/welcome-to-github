## 研究摘要

本日测试一个 observability shortcut: 如果多个事件共享同一 conversation/process correlation identity，是否可以据此把它们当成同一次具体 execution attempt

OpenAI Agents SDK current contract 明确把 `group_id` 定义为可跨多个 runs 关联 traces 的 grouping identifier，同时 `trace_id` 是单个 trace 的 identity

MCP 2026-07-28 又把 request identity 与 tracing metadata 分开，并明确 transport response stream 中断后，原 in-flight request 丢失，client 必须重新发起一个具有新 request ID 的 request

因此 higher-level correlation continuity 不足以证明 single-attempt continuity

## 研究问题

当 Agent 或 protocol observability 中存在稳定的 correlation/group identity 时，能否仅凭该 identity 推断相关事件属于同一次 concrete execution attempt

## 可证伪假设

- 支持条件: 至少一个当前权威合同允许同一 group/correlation 关联多个 traces 或 runs，并且另一个独立合同要求 logical reissue 产生新的 concrete request identity
- 推翻条件: 当前合同要求 correlation/group identity 与 execution attempt 一一对应，且 retry/reissue 必须保持同一 trace/request identity

## 实验设计

### Trial A

- 目的: 测试 higher-level group identity 是否与 single trace/run identity 一一对应
- 保持条件: OpenAI Agents SDK tracing surface
- 改变条件: one group across multiple runs/traces
- 预期支持结果: same `group_id` can relate multiple distinct traces/runs
- 预期反证结果: SDK contract requires a unique group per single trace/run

### Trial B

- 目的: 测试 logical operation continuity 是否要求保持 concrete request identity
- 保持条件: MCP 2026-07-28 logical client request after transport interruption
- 改变条件: intact response stream versus broken response stream requiring reissue
- 预期支持结果: reissue uses a new request ID
- 预期反证结果: interrupted request resumes under the original request ID

### Trial C

- 目的: 跨 publisher 测试 correlation continuity 是否足以建立 single execution-attempt identity
- 保持条件: higher-level logical relation remains meaningful
- 改变条件: trace/run grouping and request reissue boundaries
- 预期支持结果: correlation/group and attempt identities remain separate coordinates
- 预期反证结果: both contracts enforce one-to-one correlation-to-attempt mapping

## 原始观测

1. OpenAI current Running agents documentation states that `group_id` can link traces across multiple runs
2. OpenAI current Tracing documentation assigns a unique `trace_id` to each trace while allowing `group_id` to associate multiple traces from the same conversation or process
3. OpenAI therefore exposes at least two distinct observability coordinates: trace identity and cross-trace grouping identity
4. MCP 2026-07-28 documents W3C trace-context propagation using `traceparent`, `tracestate` and `baggage` metadata
5. MCP 2026-07-28 removes stream resumability for an interrupted in-flight request and requires reissue as a new request with a new request ID
6. MCP schema defines `RequestId` as the identifier of a concrete JSON-RPC request and uses it when referring back to a previously issued request
7. No runtime retry, trace export, request log or correlation ledger was executed in this research window

## 反例检查

最强反例是某个应用明确规定每个 execution attempt 都生成全新的 correlation/group ID，并禁止跨 attempt 复用

在这种受控 harness 中，correlation ID 可以与 attempt identity 建立一一映射

该反例不推翻本轮，因为本轮否定的是从 generic correlation/group identity 自动推导 attempt identity，而不是禁止应用人为建立 stronger contract

另一个反例是某些 uninterrupted single-run workflow 恰好只有一个 trace、一个 request 与一个 group，在该局部样本中这些 ID 可能数值上一一对应，但 coincidence 不等于 protocol/runtime contract equivalence

当前状态为 PARTIAL

```text
CORRELATION_CONTEXT
!= EXECUTION_ATTEMPT_IDENTITY
```

Agent evidence ledger 在 retry、resume、multi-run conversation 或 distributed tracing 场景中，至少应分别保存 logical operation ID、correlation/group ID、trace ID、request/attempt ID、retry ordinal、transport interruption relation 与 final result identity

当前只有 documentation/specification evidence，没有 runtime trace，因此不声称任何具体 deployment 已正确维护这些字段，也不量化 duplicate effect 或 retry safety

## AGI-scale relevance boundary

长期自主 Agent 会跨多轮、多 run、多工具和 transport retry 维持同一个高层任务

如果系统只保存 conversation ID、group ID 或 trace correlation，而不保存 concrete attempt identity，后续 auditor 可能无法区分 retry、duplicate effect、partial execution 与真正 continuation

本轮建立的是 evidence/runtime identity boundary，不构成模型能力或 AGI capability 声明
