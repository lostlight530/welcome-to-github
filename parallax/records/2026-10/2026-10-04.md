## 研究摘要

本日测试一个常见 handoff shortcut: 文档或代码中都出现 input/context 字样时, 是否可以把 handoff tool payload, receiving agent 实际获得的 model input, 以及应用侧 local context 当成同一个数据平面

OpenAI Agents SDK current Handoffs contract 明确说明 `input_type` 只描述 handoff tool call 自身的 arguments, 这些 JSON arguments 在本地校验后传给 `on_handoff`, 它不会替换 next agent 的 main input

同一 contract 又明确 receiving agent 默认继承 prior conversation history, 而 `input_filter` / `HandoffInputData.input_items` 可以改变实际转发给 next agent model 的 input surface

Context contract 则把 `RunContextWrapper.context` 定义为 local application state/dependencies, 并明确 context 不会自动发送给 LLM

因此本轮得到 bounded result: 三个 surface 都可能参与同一次 handoff lifecycle, 但它们不是同一 identity

## 研究问题

在 OpenAI Agents SDK handoff 中, `input_type` payload, receiving agent 的 main/model input 与 `RunContextWrapper.context` 是否可以被当成同一个 "handoff input" identity

## 可证伪假设

- 支持条件: current contract 明确把 handoff tool arguments, forwarded receiving-agent input 与 local application context 分成不同字段, 生命周期或可见性规则
- 推翻条件: current contract 要求这三者始终保存同一数据, 具有同一可见性, 且修改任一 surface 必然等价修改另外两者

## 实验设计

### Trial A

- 目的: 测试 handoff `input_type` payload 是否等于 next agent main input
- 保持条件: same handoff object and same receiving agent
- 改变条件: handoff tool-call JSON arguments
- 预期支持结果: parsed arguments进入 `on_handoff`, 但 receiver 仍通过 conversation/history input surface获得 model input
- 预期反证结果: contract states `input_type` directly replaces the next agent's main input

### Trial B

- 目的: 测试 receiver model input 是否由独立 forwarding surface控制
- 保持条件: same sender, receiver and handoff destination
- 改变条件: default history versus `input_filter` / `input_items`
- 预期支持结果: receiving model-visible history can change without redefining the handoff tool payload
- 预期反证结果: receiving input is immutable once handoff arguments are fixed

### Trial C

- 目的: 测试 local application context 是否等于 LLM-visible receiving context
- 保持条件: same run and same handoff lifecycle
- 改变条件: `RunContextWrapper.context` application object
- 预期支持结果: local context is available to callbacks/tools but is not automatically passed to the LLM
- 预期反证结果: SDK contract states the entire local context object is always injected into receiving-agent model input

## 原始观测

1. OpenAI current Handoffs documentation states that `input_type` describes handoff tool-call arguments
2. The model-generated JSON is validated locally and the parsed object is passed to `on_handoff`
3. The same documentation explicitly states that `input_type` does not replace the next agent's main input
4. By default the receiving agent sees previous conversation history, unless forwarding is changed by `input_filter` or handoff-history settings
5. `HandoffInputData.input_items` can define items forwarded to the next agent while `new_items` remain available for session history, demonstrating model-input and history-storage surfaces need not be identical
6. OpenAI Context management defines `RunContextWrapper.context` as app-defined local state/dependencies used by tools, callbacks and hooks
7. Run context reference explicitly states that contexts are not passed to the LLM
8. No Agents SDK runtime handoff, trace bundle or receiver model-request payload was captured in this research window

## 反例检查

最强反例是应用可以主动把同一结构化对象同时写入 handoff `input_type`, receiving-agent forwarded input 与 `RunContextWrapper.context`

在这种具体 harness 中, 三个 surface 的内容可以碰巧完全相同

这不推翻本轮, 因为内容相同不等于 contract identity 相同: 三个 surface 仍具有不同 producer, consumer, visibility 与 mutation rules

第二个反例是应用可以在 `on_handoff` 中读取 parsed payload, 再手工修改 local context, 或通过其他机制把同一值加入 receiving model input

这证明 surface 之间可以被应用显式桥接, 但也反向说明 bridge 是额外 application logic, 不是 SDK 自动等价

Agent runtime/evidence ledger 若要解释 handoff, 至少应分别记录 handoff tool arguments, receiver-visible input/history transform, local application context reference/version 与 explicit bridge logic

当前只有一个 publisher family 且没有 runtime capture, 所以本轮不推广为跨框架普遍实现事实, 也不声称任何具体 production handoff 已产生 context leak 或 provenance loss

## AGI-scale relevance boundary

长期自主 Agent 的 delegation 经常同时存在 model-generated routing metadata, receiver-visible task history 与 code-side state/dependencies

如果 observability layer 把它们全部压成一个 `context` 或 `handoff_input` 字段, 后续 auditor 将无法判断某个信息究竟由模型生成, 被显式转发, 还是只存在于本地 runtime

本轮建立的是 context-plane identity boundary, 不构成模型能力或 AGI capability 声明
