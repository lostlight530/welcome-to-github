## 研究摘要

本日研究同一个 JSON Schema-valid tool result 在不同 MCP 版本下是否仍具有相同 wire admissibility, 以及 schema-valid 与 wire-compatible 是否足以证明跨 Agent 的任务产物已绑定并得到业务验收

MCP 2025-11-25 Tools 规范限定 structuredContent 为 JSON object, 2026-07-28 版本文档允许任意 JSON value, 同一发布者的两版文档不是两个独立来源

JSON Schema Draft 2020-12 的 schema validation 只对已声明的 instance assertions 进行判断, 不自动证明远端执行、Task/Artifact 关联或客户端验收, A2A 的 Artifact ID 作用域和 Task 对象又处于独立协议层

本地真实执行 jsonschema 4.26.0 validator 加研究者自定义 version/acceptance gate, 24 个确定性 cases 与 129 项断言全部通过, 输出 21 schema-valid、19 wire-root-shape-allowed、15 usable、12 task-bound、9 application-accepted

## 研究问题

如果结构化工具输出通过 JSON Schema 2020-12 验证, 是否可以在 MCP 2025-11-25 和 2026-07-28 之间不经 root-shape 检查而复用, 并进一步把同一结构化输出视为已经关联正确 A2A Task、产生有效 Artifact 且获得客户端业务接受

## 可证伪假设

- 支持条件: MCP 旧版与新版对 structuredContent 根类型存在明确不同的文字合同; 同一真实 Draft202012Validator 在版本对照中保持相同 instance-valid 结果, 但旧版非 object 被单独的 wire-shape gate 拒绝; task/artifact/effect/acceptance 负例不能因 schema-valid 自动通过
- 推翻条件: 版本规范要求两个版本都允许任意根类型, 或真实 schema validator 与合成 fixture 的受控预期相矛盾, 或 A2A 规范直接赋予任意 MCP schema-valid 结果跨系统 task/acceptance 的充分证明
- 解释范围: 文档合同与本地显式 policy gate, 不是 MCP/A2A 官方端到端 conformance suite

## 实验设计

### Trial A｜MCP versioned output root 的合同对照

- 目的: 区分 JSON Schema instance validity 与 MCP negotiated-version root admissibility
- 保持条件: 相同 JSON instance、schema、validator 和 source cut
- 改变条件: 2025-11-25 或 2026-07-28 version label, object/array/scalar root
- 预期支持结果: object 与 object-wrapped array 在两版本均可通过根形状门槛, 直接 array/scalar 仅在 2026-07-28 形状门槛可通过
- 预期反证结果: 官方文本没有版本差异, 或 fixture 对相同 instance/schema 的验证结果随版本无故改变

### Trial B｜真实 JSON Schema 断言与 downstream acceptance 的分离

- 目的: 在保留同一 schema-valid 结果时改变 tool error、task identity、artifact binding、task terminal、effect receipt 与 client acceptance
- 保持条件: Python/jsonschema 版本、schema、baseline object value、同一 gate 实现
- 改变条件: 每个负例一个 error 或对象归属/业务接受字段, schema-invalid controls 另行改变 instance 的一个结构特征
- 预期支持结果: schema-valid 不能充分证明后续 task binding 或 application accepted, 24-case expected vector 全部通过
- 预期反证结果: 任一负例在最终 policy gate 未被拒绝, 或预期计数与实际执行不一致
