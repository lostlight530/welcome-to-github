## 研究摘要

本日测试一个协议层 shortcut：如果两个系统都暴露“需要用户输入/保持同一逻辑操作”的 capability，是否可以据此推断它们具有相同的 wire interaction shape

MCP 当前 2026-07-28 lifecycle 不允许 server-initiated requests；需要中途输入时，server 返回 `input_required`，由 client 处理 embedded request 并重试原请求。旧 handshake-era connection 则允许 server-to-client elicitation request。A2A 对 custom protocol binding 的要求恰好从另一方向提供控制：binding 可以改变 transport，但必须保持 core operations 与 data model 的 functional equivalence

因此 logical capability preservation 不等于 wire-direction、round-trip shape 或 transport identity 保持不变

## 研究问题

跨 protocol revision 或 transport binding 观察到同一 logical capability 时，能否把 wire interaction shape 当成同一 execution identity

## 可证伪假设

支持条件：至少一个权威协议合同允许 logical capability 在不同 wire direction/round-trip mechanism 下保持，而另一个独立协议合同明确要求 transport binding 变化时保持 logical operation equivalence。推翻条件：current contracts 要求 logical capability equivalence 必然保持相同 request direction、round-trip structure 与 transport identity

## 历史背景

## 原始观测

1. MCP 2026-07-28 被当前 SDK 文档描述为 modern stateless lifecycle，不再使用 initialize handshake
2. MCP legacy connection 上 elicitation 可以表现为 server-to-client request
3. MCP 2026-07-28 上需要输入时改为 `input_required` result，client 处理后重试原 request
4. MCP TypeScript SDK 文档进一步明确 2026-07-28 没有 server-initiated completion signal
5. A2A custom binding 可以使用不同 transport，但必须支持全部 core operations 并保持 functionally equivalent data model
6. 本轮没有运行 MCP 双版本 trace，也没有实现 A2A custom binding interoperability test

## 反例检查

如果两个实现不仅保持 logical capability，还固定同一 protocol revision、同一 binding、同一 transport、同一 request direction 和同一 resume contract，那么 wire interaction shape 可以在该受控范围内视为相同。该反例不推翻本轮，因为被否定的是仅凭 capability equivalence 推导 wire identity

A2A 的 binding requirement 也不是“任何 transport 差异都无关”：它要求所有 core operations 行为一致，并要求 intentional deviations 明确记录，因此 transport replacement 仍需要 interoperability verification
