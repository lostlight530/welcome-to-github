## 研究摘要

本批次使用 Cloudflare 官方 rate limiting 工程分析作为 P-03 的第三类分母对象

页面直接给出分析覆盖 400 million requests from 270000 distinct sources, 同时报告 0.003% of requests 被错误允许或错误限流, 以及 3 sources 在略高于阈值时仍被允许

这里同时存在 request-level 分母与比例, 以及 source-level false-negative 计数

本轮检查直接请求分母出现后可以支持什么量化, 并主动拒绝把 3 sources 改写为 3 requests, 或把页面显示的 0.003% 机械乘以 400 million 后得到的 12000 当作 Cloudflare 直接发布的精确错误请求数

结果推进 N-02 的边界: 有分母时允许有边界量化, 但统计单位和公开精度仍决定可以声称到什么粒度

## 研究问题

当官方工程分析同时给出 400 million request 总分母, 0.003% request-level 错误比例与 3 source-level false negatives 时, 判断能否保留各自统计单位

直接分母出现是否足以形成精确错误请求计数, 还是仍需要发布者直接给出同单位 numerator 或足够精度信息

## 可证伪假设

- 支持条件: 接受 400 million requests 与 0.003% of requests 的有边界比例描述, 将 3 保持为 sources, 删除分母或单位后判断收窄, 不把机械乘法结果写成原始精确计数
- 推翻条件: 把 3 sources 写成 3 requests, 把 0.003% 无条件转换为官方精确 12000 requests, 或把 none of the mitigated sources below threshold 写成所有其余 requests 都被正确分类

## 历史背景

2026-08-18 GitHub 事故报告给出 1700 万 Git proxy requests 总分母, 但不同处理阶段的请求数不能机械相减形成完整失败量

2026-08-19 Cloudflare outage 给出约 28% 与 all HTTP traffic served by Cloudflare 的总体身份, 但没有数值总请求量

P-03 当前下一复验条件因此要求寻找同时具有数值请求总量和失败数或成功数的独立发布者, 并保持请求对象, 时间窗口与统计层级一致

本轮 Cloudflare 工程分析提供数值 request 分母与 request-level 比例, 但精确 request-level numerator 仍未直接发布, 同时存在 source-level 计数, 因而适合检查最后的统计单位边界

## 实验设计

### Trial A

- 目的: 建立完整统计基线
- 保持条件: E1 的 request 分母, request 比例, source 分母与 source false-negative 计数
- 改变条件: 无
- 预期支持结果: 分别保存 request-level 与 source-level 统计, 不生成未公开 numerator
- 预期反证结果: 合并统计单位

### Trial B

- 目的: 直接执行 P-03 关键缺失变化
- 保持条件: 0.003% of requests, 270000 sources 与 3 sources
- 改变条件: 删除 400 million requests
- 预期支持结果: 保留公开比例但 request 总分母未知, 不产生精确错误请求数量
- 预期反证结果: 从其他字段补出 400 million 或精确 numerator

### Trial C

- 目的: 检查统计单位身份
- 保持条件: 数字 400 million, 270000, 0.003%, 3
- 改变条件: 删除 requests 与 sources 单位标签
- 预期支持结果: 数字存在但层级关系未知, 不进行跨单位相除或相减
- 预期反证结果: 默认把全部数字当作 request count

### Trial D

- 目的: 检查机械反推精度
- 保持条件: E1 完整公开字段
- 改变条件: 加入 C1
- 预期支持结果: 12000 只标记为由公开显示比例构造的压力计算, 不改写为 Cloudflare 原始精确观测
- 预期反证结果: 接受精确 12000 作为发布者事实

### Trial E

- 目的: 检查 source 与 request 混淆
- 保持条件: E1 完整公开字段
- 改变条件: 加入 C2
- 预期支持结果: 拒绝 3 sources = 3 requests 和其余请求全部正确两个结论
- 预期反证结果: 允许跨单位等同

## 原始观测

- Trial A: E1 直接记录 400 million requests 与 270000 distinct sources, 两个分母属于不同单位
- Trial A: E1 直接记录 0.003% of requests wrongly allowed or rate limited, 这是 request-level 比例
- Trial A: E1 直接记录 3 sources 被错误允许, 这是 source-level false-negative 数量
- Trial B: 删除 400 million requests 后, 0.003% 仍是公开比例, 但本 Trial 输入没有数值 request 总分母
- Trial C: 删除单位后无法判断 3 与 270000 是否和 400 million 属于同一统计对象
- Trial D: 12000 可以由显示数字机械计算, 但页面没有直接发布这一 numerator, 也没有给出 0.003% 的底层精度, 因而不能标记为精确原始观测
- Trial E: 3 sources 与 requests 单位不同, none of the mitigated sources was below threshold 也不能推出所有其余 requests 都被正确分类

## 反例检查

- 400 million requests 与 270000 sources 不是同一统计单位
- 3 false-negative sources 不能改写为 3 false-negative requests
- 0.003% of requests 是公开比例, 不等于页面直接发布精确错误 request numerator
- 机械计算 12000 依赖把显示比例当作足够精确的精确比例, 只能作为压力计算而非原始观测
- none of the mitigated sources was below threshold 不能改写为所有未列请求均正确
- 页面结论中的 several billion requests per day 与 400000 requests per second 属于产品运行或攻击规模描述, 不能替代 400 million analysis dataset 的分母

反例成立并限制本次观察
