## 研究摘要

本批次使用 Cloudflare 2026-06-22 关于 Images binding 与 hyper HTTP library race condition 的官方技术复盘复验 P-03

Cloudflare 在生产路径复现过程中使用批量请求脚本, 其中一次早期运行直接报告 25 个请求中 19 个失败

同一复盘同时说明 Images service 层面对这些请求都返回 HTTP 200, 但失败请求的响应正文被截断, 外层处理因此出现 body length 不完整错误

因此 direct total 25 与 direct failed numerator 19 支持该次复现运行内的精确失败计数

19/25 可构造得到 76% failure rate, 但该百分比是本轮依据发布者直接计数计算的派生值, 不是 Cloudflare 在该段直接发布的百分比字段

25-19 可构造得到 6 个未失败请求, 但该数值是算术 residual, 不能改写为 Cloudflare 直接发布的 exact successful numerator 字段

HTTP 200 on every request 也不能替代语义 outcome, 因为同一材料明确记录部分请求虽然服务层返回 200, 实际 body 已被截断并在外层失败

本轮没有运行 Cloudflare reproduction worker, 没有执行 25-request batch, 没有访问生产 Images binding, 也没有取得当前 runtime response sample

## 研究问题

当发布者直接给出同一受控复现批次的 total requests 与 exact failed requests, 但 successful count 与 failure rate 没有作为直接字段发布时, 是否允许保留可复算的派生值同时继续区分 direct observation 与 arithmetic derivation

当删除 direct total 或 direct failed numerator, 或使用 HTTP 200 status 替代 semantic failure outcome 时, 判断是否会重新收窄而不是补全缺失统计

## 可证伪假设

- 支持条件: 完整材料中保留 direct total=25 与 direct failed=19, 76% 明确标为 derived rate, 6 明确标为 arithmetic residual, 删除 total 或 failed numerator 后对应精确率失去直接计算基础, HTTP 200 不被扩大为 semantic success
- 推翻条件: 把 76% 写成发布者直接给出的原始比例, 把 6 写成发布者直接 successful numerator, 删除 total 或 failed numerator 后仍声称保留同等精确统计, 或依据 HTTP 200 断言 25 个请求全部语义成功

## 原始观测

- Trial A: Cloudflare 直接报告 one early run 中 19 out of 25 requests failed, 同一复盘说明 Images service returned 200 on every request, 因此 HTTP status 与 semantic outcome 在该 bug 中不等价
- Trial B: 删除 total=25 后仍可保留 direct failed=19, 但 denominator 消失, 不能保持 76% 这一同等精度比例判断
- Trial C: 删除 failed=19 后只剩 total=25 和 HTTP 200 behavior, 这些材料不能支持 exact semantic failure count, 也不能支持 0 failures
- Trial D: C3 与 truncated response, outer error 和 direct 19 failures 冲突, 因而被拒绝
- Trial E: 19/25 可复算为 76%, 25-19 可复算为 6, 但网页原文在该段直接发布的是 25 与 19, 因而 76% 与 6 必须保留 derived identity

本轮没有运行 reproduction worker, 没有执行 hyper integration test, 没有发起 Cloudflare Images 请求, 没有取得当前生产 response bytes

- local macOS 与 Debian VM reproduction 没有触发 failure, 反驳该 bug 在所有环境稳定复现
