## 研究摘要

本专题使用 OpenAI Models API 复验 HTTP 401 能否单独支持具体认证原因

不提供 Authorization 请求头时, Models endpoint 返回 HTTP 401, 正文标识 Missing bearer authentication in header

提供固定无效 Bearer 值时, 同一端点仍返回 HTTP 401, 正文代码变为 invalid_api_key

OpenAI API 参考要求使用 HTTP Bearer 认证, 错误代码指南同时列出多种 401 原因

只有端点身份与 401 状态时, 判断保持具体原因未知

加入可检查的请求条件与认证契约后, 可以分别确认缺失 Bearer 与错误凭据不符合要求

加入响应正文后, 可以确认当前两次请求采用不同诊断

来源逆序没有改变边界, 额度耗尽摘要被 401 状态, 请求条件与错误指南反驳

## 研究问题

相同 OpenAI API 端点返回 HTTP 401 时, 状态码能否区分缺失认证与无效凭据

请求条件, 官方认证契约与响应正文分别能够支持多具体的归因

来源顺序和额度耗尽摘要是否改变判断边界

## 可证伪假设

- 支持条件: 只有 401 时拒绝选择具体认证原因, 加入请求条件与契约后只确认条件违反, 加入正文后区分缺失 Bearer 与无效凭据, 逆序与误导摘要不改变边界
- 推翻条件: 从 401 单独补出缺失请求头, 把两次 401 写成同一原因, 或采用与 401 和直接正文冲突的额度耗尽摘要

## 反例检查

- R1 正文证明直接诊断存在时可以形成具体原因, 反驳所有 401 都必须保持未知
- R2 以相同 401 返回不同原因, 反驳状态码能够单独识别缺失认证
- E3 列出多种 401 原因, 反驳 401 必然等于错误密钥
- E3 把额度与速率问题列在 429, 反驳 C1 对当前 401 的解释
- 固定无效测试值不能证明任何真实密钥失效
- 两次认证失败不能证明 Models API 对有效凭据不可用

反例成立并限制扩展范围

## 暂时结论

本批次形成 P-02 的第五次观察与 N-01 失效检查

在 OpenAI Models API 场景中, HTTP 401 单独不足以区分缺失 Bearer 与无效凭据

可检查的请求条件与官方契约支持条件违反, 直接响应正文进一步支持本次具体诊断

相同状态异因反例, 来源逆序与额度误导摘要没有改变边界

N-01 保持有效, 适用边界增加本次 OpenAI HTTP 401 场景

本次没有证明该结论适用于所有 401, 所有 API 或所有执行主体
