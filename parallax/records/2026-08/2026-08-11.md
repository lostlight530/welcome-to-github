## 研究摘要

本批次选择 Kubernetes 官方 Deprecated API Migration Guide 中同一组 FlowSchema 与 PriorityLevelConfiguration 的版本迁移链

v1.26 边界停止提供 `flowcontrol.apiserver.k8s.io/v1beta1`, 官方迁移目标为 `flowcontrol.apiserver.k8s.io/v1beta2`

v1.29 边界进一步停止提供 `flowcontrol.apiserver.k8s.io/v1beta2`, 官方迁移目标更新为 `flowcontrol.apiserver.k8s.io/v1` 或 `flowcontrol.apiserver.k8s.io/v1beta3`

五个 Trial 检查明确版本生效时间能否更新当前契约判断, 同时保留 v1.26 的历史迁移关系, 并在删除时间或对象身份后收窄替代关系

结果支持 P-04 核心变化在本轮直接执行

## 研究问题

对同一组 Kubernetes 流控资源, 官方迁移契约从 v1.26 到 v1.29 发生更新时, 判断能否按明确版本和发布日期更新当前 API 选择, 同时保留旧版本边界内的历史迁移原因

删除版本时间或稳定对象身份后, 是否会拒绝把两次迁移机械拼成确定替代链

## 可证伪假设

- 支持条件: 只给出 v1.26 契约时保留 `v1beta1 → v1beta2` 的历史判断, 加入 v1.29 契约后更新为 `v1beta2 → v1 或 v1beta3`, 删除时间后保留相对迁移链但拒绝把它映射为具体发布边界或当前适用性, 删除对象身份后拒绝确定两次迁移属于同一对象链
- 推翻条件: 加入 v1.29 明确移除后仍把 v1beta2 作为 v1.29 当前服务版本, 或删除版本时间后仍无条件断言某具体发布版本的当前契约, 或删除对象身份后仅凭相似 deprecated 措辞确定同一替代链

## 原始观测

### Trial A

E1 的 v1.26 条目明确说明 `flowcontrol.apiserver.k8s.io/v1beta1` 的 FlowSchema 与 PriorityLevelConfiguration 自 v1.26 起不再提供

同一条目要求将清单和 API 客户端迁移到 `flowcontrol.apiserver.k8s.io/v1beta2`

E3 确认 Kubernetes v1.26 于 2022-12-09 正式发布, 并把 v1beta1 flow control API group removal 列入该版本的 deprecations and removals

判断限定为 v1.26 历史边界: v1beta1 已停止提供, v1beta2 是当时正式迁移目标

### Trial B

E2 的 v1.29 条目明确说明 `flowcontrol.apiserver.k8s.io/v1beta2` 的同一组 FlowSchema 与 PriorityLevelConfiguration 自 v1.29 起不再提供

E2 要求迁移至 `flowcontrol.apiserver.k8s.io/v1`, 该版本自 v1.29 可用, 或迁移至 `v1beta3`, 该版本自 v1.26 可用

E4 确认 Kubernetes v1.29 于 2023-12-13 正式发布并再次明确 v1beta2 flow control API 不再提供

当前判断因此更新到 v1.29 边界, 同时保留 Trial A 对 v1.26 历史契约的判断

### Trial C

删除作为时间锚点的 v1.26, v1.29 发布边界标签与两个发布日期后, 输入仍保留 `v1beta1 → v1beta2` 和 `v1beta2 → v1 或 v1beta3` 的相对迁移方向

因此可以从输入识别相对迁移链, 但不能由本 Trial 输入恢复它对应的具体 Kubernetes 发布边界或日历生效时点

在没有给定当前 Kubernetes 发布版本的条件下, 本 Trial 也不把任一 API 版本无条件声明为某个现实集群的当前适用契约

### Trial D

删除 FlowSchema, PriorityLevelConfiguration 与 API group 后, 输入只剩不同 beta, stable 版本之间的弃用与迁移描述

这些通用措辞不足以证明两组说明针对同一资源集合

判断拒绝建立确定连续替代链

### Trial E

C1 声称 v1beta2 在 v1.29 后仍是当前推荐版本

该摘要与 E2, E4 对 v1.29 停止提供 v1beta2 的直接官方说明冲突

判断拒绝 C1, 保留 v1beta2 在 v1.26 历史边界曾是迁移目标, 但在 v1.29 边界已停止提供的时间限定关系

## 暂时结论

本日日报形成 P-04 第六个研究批次与第六个独立执行窗口

在本次 Kubernetes 官方契约中, 明确版本生效时间允许当前判断从 v1.26 的 `v1beta1 → v1beta2` 历史迁移关系更新到 v1.29 的 `v1beta2 → v1 或 v1beta3`

## 已验证事实

- Kubernetes 官方迁移指南说明 v1.26 停止提供 `flowcontrol.apiserver.k8s.io/v1beta1` 的 FlowSchema 与 PriorityLevelConfiguration, 并要求迁移到 v1beta2
- Kubernetes 官方迁移指南说明 v1.29 停止提供 `flowcontrol.apiserver.k8s.io/v1beta2` 的相同资源, 并要求迁移到 v1 或 v1beta3
- v1.29 迁移条目说明 v1 自 v1.29 可用, v1beta3 自 v1.26 可用
- v1.29 迁移条目说明 PriorityLevelConfiguration 的 `spec.limited.assuredConcurrencyShares` 在 v1 与 v1beta3 中更名为 `spec.limited.nominalConcurrencyShares`
- Kubernetes v1.26 正式发布公告日期为 2022-12-09
- Kubernetes v1.29 正式发布公告日期为 2023-12-13
- Kubernetes v1.29 正式发布公告确认 deprecated v1beta2 flow control API 在 v1.29 不再提供

## 合理推断

- 对本次固定资源对象, v1.26 与 v1.29 构成可排序的两个正式契约边界
- 在评价给定 Kubernetes 发布版本的 API 契约时, v1.29 的较新 removal 关系应更新 v1.26 时点对 v1beta2 的历史迁移判断
