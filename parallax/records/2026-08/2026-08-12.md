## 研究摘要

本批次选择 Python 官方 PEP 632, Python 3.10 发布页, Python 3.12 文档与 Python 3.12 发布页中的 `distutils` 生命周期

Python 3.10 将标准库 `distutils` 正式标记为 deprecated, PEP 632 同时说明 Python 3.10 与 3.11 保留该模块但发出弃用警告

Python 3.12 将 `distutils` 从标准库移除, 官方文档明确说明最后一个仍提供标准库 `distutils` 的版本是 Python 3.11

五个 Trial 检查较新的 removal 契约是否更新当前判断并保留 3.10 的历史弃用边界, 同时检查时间锚点缺失, 对象身份缺失与第三方兼容实现造成的冲突摘要

结果支持 P-04 核心变化在另一独立发布者上再次直接执行

## 研究问题

对同一个 Python 标准库模块 `distutils`, 官方契约从 Python 3.10 的 deprecated 更新到 Python 3.12 的 removed 时, 判断能否按明确版本与发布日期更新当前标准库状态, 同时保留 Python 3.10 时点的历史弃用原因

当删除版本时间或 `distutils` 对象身份后, 是否会收窄判断边界

当第三方 `setuptools` 仍可提供 `distutils` 时, 是否会错误地把第三方兼容提供解释为 Python 3.12 标准库仍包含该模块

## 可证伪假设

- 支持条件: 只给出 Python 3.10 契约时保留 `distutils` 已 deprecated 但仍属于标准库的历史判断, 加入 Python 3.12 契约后更新为标准库已移除, 同时保留 3.10 的历史边界
- 时间删除条件: 删除 Python 3.10, Python 3.12 与对应发布日期后仍可识别 deprecated 到 removed 的相对生命周期, 但不能把生命周期映射到具体发布版本或日历日期
- 身份删除条件: 删除 `distutils` 对象身份后不能把两组通用 deprecated 与 removed 文本确定为同一个模块的连续契约
- 冲突条件: `setuptools` 仍可提供 `distutils` 不得覆盖 Python 3.12 标准库已经移除 `distutils` 的正式契约
- 推翻条件: 加入 Python 3.12 明确 removal 后仍把标准库 `distutils` 写成 Python 3.12 自带模块, 或删除时间与身份后仍补出确定发布边界与对象链

### Trial C

删除 Python 3.10, Python 3.12 与两个发布日期后, 输入仍明确表达同一 `distutils` 对象先 deprecated 后 removed

判断收窄到生命周期顺序, 不补全发布锚点

### Trial D

删除 `distutils` 模块名称后, 输入只剩一个标准库对象从 deprecated 到 removed 并建议迁移至第三方或替代 backend 的通用描述

这些措辞不足以证明所有片段针对同一个模块

判断拒绝建立确定对象链

### Trial E

C1 把 `setuptools` 仍能提供 `distutils` 解释为 Python 3.12 标准库仍包含 `distutils`

E3 与 E4 明确把两件事分开: Python 3.12 标准库已经移除 `distutils`, 需要时可以安装第三方 `setuptools`

判断拒绝 C1, 保持标准库身份与第三方兼容提供的边界

## 合理推断
