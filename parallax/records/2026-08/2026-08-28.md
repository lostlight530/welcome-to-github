## 研究摘要

本批次使用 Google DeepMind 2026-08-27 发布的 double-blind AI evaluation pilot 复验 P-05

DeepMind 将本次对象描述为 proprietary frontier-class model 的 double-blind evaluation pilot, 并说明合作方包括 Singapore AI Safety Institute, OpenMined, AVERI 与 MLCommons

公开页面把具体测试对象限定为一个 Gemini Flash Lite model 与 confidential benchmarks, 没有在正文中发布本轮 benchmark score 或能力排名

页面说明历史外部评估存在测试 prompts 交给模型提供方或模型权重交给评估者的 tradeoff

本次 pilot 使用 Google Cloud Confidential Space, 页面声称可通过 cryptographic verification 保持 external evaluation data 与 proprietary model 分别对其所有者私密

该页面进一步明确 evaluator 不能看到 Gemini model weights, Google 不能看到 evaluator test prompts

这些条件支持记录 evaluation protocol, model identity, evaluator identity 与 benchmark-confidentiality 边界, 但不能从 pilot 机制本身推出模型已通过安全评估, benchmark 结果没有 contamination, 或所有外部评估均已采用 double-blind protocol

本轮没有运行 Confidential Space, 没有取得该 pilot 的 confidential benchmark prompts, model weights 或 evaluation outputs, 也没有执行技术报告中的环境复现

## 研究问题

当官方页面同时提供 evaluation pilot, confidential benchmark, model identity, evaluator identity 与 cryptographic isolation 条件时, 长上下文能否保持这些对象边界而不把协议设计升级为能力结果

删除 confidentiality 条件或模型与评估者身份后, 判断是否会主动收窄而不是根据 double-blind 标签补全缺失事实

## 可证伪假设

- 支持条件: 完整材料中只确认本次 Gemini Flash Lite double-blind evaluation pilot 与公开协议边界, confidentiality 条件删除后不再声称本轮具有同等 cryptographic isolation 证明, 身份删除后不猜测谁持有模型或 benchmark, 不把 pilot 写成 capability or safety result
- 推翻条件: 将 double-blind 标签直接写成模型安全通过, 将 benchmark contamination risk 写成已被全局消除, 删除 protocol condition 后仍保留同等确定判断, 或把所有外部评估扩大为相同机制

## 实验设计

### Trial A

- 目的: 建立当前 double-blind protocol 基线
- 保持条件: E1 与 E2 的模型, benchmark, participant 与 confidentiality 条件完整
- 改变条件: 无
- 预期支持结果: 只确认该 pilot 的 protocol 与双方信息隔离边界
- 预期反证结果: 从机制描述推出模型安全通过或 benchmark score

### Trial B

- 目的: 检查长上下文是否改变当前对象边界
- 保持条件: Trial A 全部事实
- 改变条件: 加入 E3 的历史 tradeoff, contamination risk 与 external evaluation 背景
- 预期支持结果: 当前 pilot 判断不因风险动机扩大为当前污染事实或所有 external evaluations 的统一状态
- 预期反证结果: 将一般 benchmark contamination 问题归因到当前模型或当前 benchmark

### Trial C

- 目的: 直接执行 P-05 的关键支持删除
- 保持条件: double-blind, external evaluation, Gemini Flash Lite 与 confidential benchmark 文本
- 改变条件: 删除 Confidential Space, cryptographic verification 与 evaluator/Google 不可见条件
- 预期支持结果: 不能继续声称本轮已经由当前输入证明同等 technical isolation
- 预期反证结果: 仅凭 double-blind 标签自动补回 cryptographic mechanism

### Trial D

- 目的: 检查模型与评估者身份删除
- 保持条件: 恢复完整 protocol 机制

- 预期支持结果: 只保留匿名双方隔离关系, 不猜测哪一方持有何种资产
- 预期反证结果: 根据上下文自动恢复具体模型, 提供方或评估者身份

### Trial E

- 目的: 压力测试 protocol → result 的错误升级
- 保持条件: 恢复 E1 至 E3 全部事实

## 原始观测

- Trial A: 当前页面直接支持一个 Gemini Flash Lite double-blind evaluation pilot, confidential benchmarks 与 Confidential Space 信息隔离机制, 没有在正文中提供本轮 benchmark result 表
- Trial B: contamination 与历史 tradeoff 解释为何需要该方法, 但没有把当前模型或 benchmark 写成已知污染对象
- Trial C: 删除技术条件后只剩 double-blind 标签和 pilot 身份, 不足以从当前输入证明具体 cryptographic isolation mechanism

本轮没有访问 confidential prompts, proprietary weights 或 enclave runtime, 没有执行技术报告复现
