## 研究摘要

本批次使用 Google Cloud Storage 的正式生产事故记录复验 P-02

2023-02-09 Google Cloud Service Health 记录一个全球 Cloud Storage incident

事件诊断明确限定为使用 CMEK objects 的 resumable uploads

受影响客户在写入 resumable upload chunk 时可能先遇到 HTTP 503

客户端重试后会收到 HTTP 410, 原因是该 upload 已经被终止

当前 Cloud Storage retry strategy 则把 HTTP 408, 429 与 5xx 归入通常值得重试的 transient responses, 同时强调是否安全重试还取决于 operation idempotency

RFC 9110 对 503 的通用语义是服务当前因临时过载或计划维护无法处理请求, 并允许服务器提供 Retry-After

因此通用 503 与 retry 契约只提供协议和产品层基线

本事件的 503→retry→410 状态转移, CMEK scope 与 terminated upload 事实必须由事件本身承担

本轮没有向 Cloud Storage 发送生产请求, 没有取得当下 503 response body, headers 或 Retry-After

## 研究问题

当通用 HTTP 503 语义, Cloud Storage 当前 retry contract 与一个具体 production incident 同时出现时, 判断是否由更直接的事件证据和对象范围决定, 而不是由来源出现顺序或通用 retry 规则决定

如果删除事件特异的 retry→410 与 CMEK scope, 是否会错误地把一般可重试语义补成该事件实际重试结果

## 可证伪假设

- 支持条件: 调换通用契约与事件证据顺序不改变判断, 完整材料只把 503→410 状态转移归于 2023-02-09 CMEK resumable-upload incident, 删除事件特异字段后判断收窄
- 推翻条件: 来源顺序改变具体归因, 仅凭 503 推断本事件一定是 overload 或 maintenance, 仅凭通用 retry contract 推断本事件 retry 最终成功, 或将 CMEK scope 扩大到所有 Cloud Storage uploads
