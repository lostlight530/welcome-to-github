## 研究摘要

本批次使用 AWS 2017 年官方 Lambda concurrency 受控负载材料复验 P-03 的统计分母方向

AWS 在同一篇官方技术文章中给出固定命令 `hey -n 5000 -c 50` 与两次受控运行的完整请求级状态分布

首次运行直接记录 5000 个请求, 其中 4997 个 HTTP 200 与 3 个 HTTP 502

将该 Lambda function 的 reserved concurrency 设为 25 后再次运行相同 5000 请求与 50 concurrency, AWS 直接记录 3076 个 HTTP 502 与 1924 个 HTTP 200, 并明确说明 3076 of the 5000 requests failed with a 502

因此本轮取得了 P-03 当前统计方向此前缺失的条件: 同一发布者, 同一稳定测试对象, 同一运行窗口内直接发布数值 total requests 与 exact failed and successful request counts

该材料是 AWS 发布的历史受控负载测试, 不是本轮环境实际运行结果, 不是 2026 当前生产事故, 也不能推广为所有 Lambda 调用表面在并发限流时都返回 502

AWS 当前 Lambda Function URL 文档明确说明 function concurrency 超过 reserved concurrency 时 Function URL 返回 HTTP 429, 形成对 502 全称化的当前官方反例

## 研究问题

当同一受控运行直接提供 total requests, exact failed requests 与 exact successful requests 时, P-03 是否应从缺失 numerator 的拒绝状态更新为对应运行粒度的精确有边界判断

当删除 exact numerator, 删除 direct denominator 或把历史 API Gateway + Lambda 502 结果扩大为当前所有 Lambda throttle 行为时, 判断是否会重新收窄

## 可证伪假设

- 支持条件: 完整请求级计数存在时允许形成该受控运行内的精确失败与成功计数, 删除 numerator 或 direct denominator 后相应判断收窄, 当前 Function URL 429 契约阻止把历史 502 推广为统一 Lambda throttle 状态
- 推翻条件: 完整同单位 total 与 exact numerator 出现后仍无条件拒绝有边界更新, 或关键计数删除后仍保留原精确结论, 或把 2017 API Gateway + Lambda 示例扩大为当前全部 Lambda 调用表面

## 实验设计

### Trial A

- 目的: 建立同一测试对象与相同负载参数下的历史基线
- 保持条件: `-n 5000 -c 50`, API Gateway endpoint, Lambda function
- 改变条件: 使用 reserved concurrency 限制前的第一次运行
- 预期支持结果: 只记录发布者直接给出的 5000, 4997 个 200 与 3 个 502
- 预期反证结果: 把少量 502 自动解释为当前生产稳定失败率或单一具体原因

### Trial B

- 目的: 直接执行 P-03 当前统计复验条件
- 保持条件: 同一 5000 total requests, concurrency 50 与同一 endpoint
- 改变条件: function reserved concurrency 设为 25
- 预期支持结果: 允许精确记录该次运行 3076 个 502 failure 与 1924 个 200 success
- 预期反证结果: 完整同单位 total 与 exact numerator 存在后仍拒绝任何对应运行粒度的精确更新

### Trial C

- 目的: 执行 P-03 关键 numerator 缺失变化
- 保持条件: direct total 5000, concurrency 配置与 throttling 背景
- 改变条件: 删除 3076 与 1924 两项 exact status counts
- 预期支持结果: exact failed 与 successful requests 回到未知, 不能从 large percentage 等描述补回精确计数
- 预期反证结果: 缺少 numerator 后仍保留 3076 或 1924 的精确判断

### Trial D

- 目的: 区分发布者直接 total 与由状态计数构造出的总量
- 保持条件: 3076 个 502 与 1924 个 200
- 改变条件: 删除 `-n 5000` 与发布者直接 5000 total 表述
- 预期支持结果: 3076+1924 可以作为构造加总, 但不能改写成 Trial 输入中仍存在的 direct denominator
- 预期反证结果: 将算术可恢复值与直接发布字段视为同一证据类型

### Trial E

- 目的: 检查历史调用表面向当前全称行为的错误扩大
- 保持条件: E1 完整历史计数与 E2 当前 Function URL 契约
- 改变条件: 注入 C2
- 预期支持结果: 拒绝 throttle 一律返回 502, 保持 API Gateway 历史示例与当前 Function URL 429 契约分离
- 预期反证结果: 根据单个历史示例覆盖不同调用表面的当前正式契约

## 反例检查

- 3076 个 502 只属于 AWS 2017 文章中该次 API Gateway + Lambda 受控运行, 不证明所有 Lambda 请求有相同比例
- 2017 历史文章不是 2026 当前生产状态报告
- 首次运行的 3 个 502 被文章自身提示可能与 cold starts 或 timeout 有关, 不能据此指定单一原因
- reserved concurrency=25 后的 3076 个 502 与文章中的 throttling 场景相关, 但不能推广为所有调用服务的 throttle status
- 当前 Lambda Function URL 文档明确说明相应 concurrency 超限返回 HTTP 429, 反驳 502 为统一 Lambda throttle 状态
- 删除 direct total 时, 3076+1924 的加总仍是构造值, 不改变该 Trial 的 direct-field 缺失事实
- direct exact counts 允许该运行内精确判断, 不证明 AWS Lambda 整体历史或当前的全局失败率

## 暂时结论

P-03 当前统计复验条件在 AWS 历史受控负载材料中得到直接满足

这一结果支持 N-02 的既有核心并扩展正式适用范围到具有直接完整请求计数的 AWS 受控负载测试, 不建立新的长期发现
