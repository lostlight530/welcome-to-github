## 研究摘要

OpenAI 当前 GPT-5.5 System Card 明确记录 2026-08-19 correction, 将 hard-negative protein binding prediction evaluation 中 GPT-5.5 的 pass@4 从先前误报的 0.4% 修正为 1.48%, 并说明旧 0.4% 实际是 pass@1

GPT-5.6 System Card 的 change log 和对应 evaluation section记录同一 correction, 但显示为 1.5%

1.48% 四舍五入到一位小数为 1.5%, 因此当前证据支持同一 correction 的展示精度差异, 不支持把两页写成互相冲突的 capability result

本批次直接执行 P-04 的时间替换核心变化, 检查较新明确 correction 是否更新 current numeric judgment, 同时保留旧错误值及其错误来源作为 correction history

## 研究问题

当同一发布者在两个当前 System Card 中记录同一 quantitative correction, 但 corrected value 使用 1.48% 与 1.5% 两种展示精度时, 是否能够保持 correction identity, metric identity, 时间关系与历史旧值, 而不把 rounding difference 压成新的能力变化或来源冲突

## 可证伪假设

- 支持条件: 恢复 correction date, model, evaluation, metric 与 correction reason 后, current judgment 更新为 corrected pass@4, 旧 0.4% 保留为曾被错误报告的 pass@1 value, 两个当前页面的 1.48% 与 1.5% 被识别为兼容展示精度
- 推翻条件: 删除关键身份或时间后仍无条件归属 correction, 将旧 0.4% 删除为从未出现, 将 1.48% 与 1.5% 自动写成两次独立测量冲突, 或把 metric reporting correction 扩大为 underlying model capability 在 8 月 19 日发生变化

## 历史背景

P-04 已在状态事件, API lifecycle, removal, rollback, multi-stage route reversal 与 security final investigation 中复验较新证据更新 current judgment 且保留历史阶段

当前下一复验条件明确允许新的 explicit correction 或 material current-state update

## 实验设计

### Trial A｜完整 correction baseline

- 目的: 建立当前 correction chain
- 保持条件: E1 与 E2 全部身份, 日期, metric 与 correction reason
- 改变条件: 无
- 预期支持结果: current pass@4 judgment 使用 corrected value, 旧 0.4% 保留为历史错误报告并注明实际属于 pass@1
- 预期反证结果: 删除旧值历史或把 correction 写成 underlying capability change

### Trial B｜删除 correction date

- 目的: 检查时间身份是否必要
- 保持条件: model, evaluation, metric, old/new values 与 reason
- 改变条件: 移除 2026-08-19 时间锚点
- 预期支持结果: 仍可识别存在 explicit correction, 但不能确定该 correction 的公开生效时间
- 预期反证结果: 在没有日期时补出具体 correction chronology

### Trial C｜删除 model/evaluation/metric identity

- 目的: 检查对象身份是否必要
- 保持条件: 0.4%, 1.48%, 1.5% 与 correction wording
- 改变条件: 移除 GPT-5.5, hard-negative protein binding prediction 与 pass@4/pass@1 identity
- 预期支持结果: 拒绝把数值归属到具体模型能力或具体 metric
- 预期反证结果: 仅凭数值自动恢复对象与 metric

### Trial D｜展示精度对照

- 目的: 检查 1.48% 与 1.5% 是否构成真正冲突
- 保持条件: 同一 correction identity 与同一发布者
- 改变条件: 对照两个当前官方页面的 corrected display precision
- 预期支持结果: 1.48% round to one decimal place = 1.5%, 当前作为 compatible display precision 保存
- 预期反证结果: 无新增实验或独立来源却宣称存在两个相互冲突的 corrected results

### Trial E｜误导 capability-change 摘要

- 目的: 构造主动反例
- 保持条件: 全部官方 correction evidence
- 改变条件: 加入摘要 `GPT-5.5 biology capability on this evaluation improved from 0.4% to 1.5% on August 19`
- 预期支持结果: 拒绝该摘要, correction 是 reporting/metric identity correction, 当前材料没有证明 underlying model capability 在该日期重新训练或发生能力跃迁
- 预期反证结果: 将 reporting correction 直接改写为 model capability change

## 反例检查

- 0.4% 不能继续作为 current GPT-5.5 pass@4 value
- 0.4% 也不能从历史中删除, 因为 change log 明确说明它曾被错误报告且实际属于 pass@1
- 1.48% 与 1.5% 不能在缺少独立 run 证据时写成两个不同 capability results
- 1.48% 到一位小数为 1.5%, 当前足以解释两个官方页面的 display difference
- GPT-5.6 System Card 中记录 GPT-5.5 correction 不意味着该 corrected metric 属于 GPT-5.6
- reporting correction 不证明 model weights, training state 或 underlying capability 在 2026-08-19 改变
- current living System Card 不等于 8 月 19 日前的冻结历史页面

## 暂时结论

P-04 在新的 quantitative evaluation correction 对象中继续成立

具有稳定 model, evaluation, metric 与 correction date 时, 当前数值应随明确 correction 更新, 旧错误值与错误来源保留为历史 correction state

同一发布者两个当前 System Card 对 corrected value 使用 1.48% 与 1.5% 时, 当前证据支持 rounding/display precision explanation, 不支持制造独立结果冲突

N-03 正式支持范围可扩展到 quantitative System Card correction 与 display-precision boundary, 原生效日期保持不变
