## 研究摘要

This native Daily compares exact Git tree object identity with execution provenance across two fresh GitHub-observed main commits. The merged Parallax PR #1014 commit and later main tip have the same tracked Parallax subtree oid even though sixteen intervening commits changed non-Parallax files and the commit-bound GitHub Checks and Actions show disjoint run IDs. A bounded JavaScript assertion procedure was actually executed, 20/20 PASS. The procedure measures evidence identity, not Parallax Python runtime behavior.

## 研究问题

Can identical tracked Parallax subtree identity across two GitHub commits justify transferring check-run, workflow-run or application-success evidence between the two commit objects as if they were the same execution?

## 可证伪假设

- 支持条件: if tree identity is sufficient, the two commits should admit a direct and justified one-to-one execution identity or a separate explicit application-settlement receipt
- 推翻条件: equal Parallax subtree oids coexist with distinct commit SHAs and disjoint executed check or workflow-run IDs without that settlement relation
- 预期判定: reject sufficiency, retaining only the narrower statement of tracked Parallax tree equality

## Identity boundary

`same Parallax subtree oid != same repository commit oid != same check-run id != same workflow-run id != application settlement`

## 反例检查

The equal Parallax subtree oid accompanied by different executed check/run IDs directly refutes the claim that a shared tracked source tree determines one execution identity. The changed historical-audits subtree is a positive counter-control showing the same tree interface resolves non-Parallax modifications. Conversely, both commits have successful executed check and workflow evidence, so it is also false that an unchanged Parallax subtree implies no CI. Empty legacy status contexts do not negate direct run records. There is no evidence identifying the cause of changed CI composition or proving any named workflow executed `parallax/tools/check.py`.

## 暂时结论

PARTIAL, exact tracked Parallax subtree equality was observed across two pinned commits but cannot be promoted into shared CI run identity, a native checker PASS, or application settlement. Explicit distinct GitHub run identifiers supply a counterexample, without establishing a causal story or second independent publisher. No new CASE support, candidate, NOTES finding, Special or Audit.
