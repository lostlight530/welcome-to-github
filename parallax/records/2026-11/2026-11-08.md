## 研究摘要

This native Daily tests whether deletion of an ordinary branch ref after a merged pull request implies that the pull request head commit and its repository-side pull-request ref are also absent. It also tests whether the PR object's base SHA can substitute for the merge commit's first parent or current main. The bounded observations show that these identities diverge for PR #923. GitHub is the sole publisher, so the result remains PARTIAL and is not generalized to every repository or pull request.

## 研究问题

After GitHub records a head-ref deletion for a merged same-repository pull request, can the ordinary heads ref become unavailable while the pull-request head ref and its commit remain retrievable, and can the PR object's base SHA safely stand in for the merge-time first parent?

## 可证伪假设

- 支持条件: The event timeline records merge followed by head-ref deletion; the ordinary heads ref is unavailable; refs/pull/923/head still resolves to the PR head SHA; the head commit remains directly retrievable; and the merge receipt is an ancestor of current main
- 推翻条件: The pull-request head ref is absent or points to another commit, the head commit cannot be retrieved, the merge receipt conflicts with the PR event, or the direct ancestry comparison shows the merge commit is not in current main
- Secondary identity test: If PR base.sha equals the merge commit's first parent at merge time, the observed identity-separation hypothesis is weakened; if they differ, the two fields must remain separately named
- Independence constraint: REST, issue events, Git refs and GitHub documentation all belong to one publisher identity; multiple GitHub endpoints do not create multiple independent sources

The ordinary branch namespace, pull-request namespace, commit-object identity, PR metadata and merge ancestry are different objects. A branch deletion event does not itself prove that every repository-side PR ref or commit object was deleted. A successful PR-head ref read does not establish that the pull-request merge ref exists. A PR object's base SHA is a source field at its own access cut, not a substitute for the merge commit's recorded parent.

### Trial B — PR base metadata versus merge ancestry

- 目的: Test whether PR base.sha, merge commit parents and current main can be collapsed into one base identity
- 保持条件: Same PR #923, merge receipt and GitHub publisher
- 改变条件: PR base field, merge commit parent list, comparison from PR base to merge first parent, and comparisons from head and merge commit to current main
- 预期支持结果: PR base SHA differs from the merge commit's first parent while direct parent and ancestry evidence still establishes the merged head and current-main lineage
- 预期反证结果: The PR base SHA equals the merge-time first parent and the head or merge commit is not an ancestor of current main

## 反例检查

The deleted ordinary head ref is a counterexample to treating a branch name as the only retained representation of a PR contribution, because refs/pull/923/head and the head commit remained retrievable. The 404 for refs/pull/923/merge is a counterexample to generalizing that all PR-specific refs remain available whenever the head ref exists. The PR base SHA differing from the merge commit's first parent is a counterexample to collapsing the PR base field into merge-time ancestry. The initial 8/9 assertion result is retained as a harness counterexample: the failed equality was an unsupported assumption, not a failure of the retrieved commit graph.

## 暂时结论

PARTIAL. For PR #923 at the 2026-11-08 access cut, the ordinary head branch ref was unavailable after a recorded head_ref_deleted event, while refs/pull/923/head and the exact head commit remained retrievable. The pull-request merge ref returned 404. The merge commit contains the PR head as its second parent and is an ancestor of current main. The PR object's base SHA is not the merge commit's first parent in this case. One GitHub repository and one PR do not establish a universal retention policy, and the REST observation does not replace a Git transport replay.

## AGI-scale relevance boundary

Delegated agents that report a branch as deleted must preserve repository identity, PR number, ref namespace, head SHA, merge SHA, parent order and observation cut. Otherwise a missing mutable branch can be laundered into a false claim that the underlying evidence object or merged contribution no longer exists. This is an evidence-contract property, not an AGI capability claim.
