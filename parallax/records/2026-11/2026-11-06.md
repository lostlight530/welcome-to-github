## 研究摘要

This native Daily tests the next frontier in the November index: whether a bounded search projection may be used as an absence certificate, or merged with independently filtered PR, event and CI collections as if all were the same dataset. Two read-only controlled Trials compare one unchanged merged-Parallax query with different result limits, then cross-check two direct PR identities against an explicit closed-PR page, a PR event timeline and exact-head Actions/Checks records. The observations are bounded to a single GitHub publisher.

## 研究问题

Can a top-N search response and one REST page certify complete PR absence or current delivery state when direct per-object records and workflow collections have different predicates and result windows?

## 可证伪假设

- 支持条件: Holding the merged-Parallax predicate constant while changing topn changes visibility of a verified merged PR, and direct per-object metadata establishes an identity that the narrower projection does not show
- 推翻条件: The smaller query is demonstrated to enumerate the same complete object set, or the alleged direct PR identity/merge event does not exist
- 独立性约束: Multiple GitHub surfaces are not multiple independent publishers, and a successful assertion against retrieved response fields is not a replay of the original PR or native Parallax checker

## 历史背景

November 4 separated open versus merged PR query predicates; November 5 separated filtered search absence from retrievable repository artifacts. November 5 later maintenance PR #903 was merged with an exact head and merge commit, which permits this new-date bounded test on result limits, page windows and event identity without creating retroactive November 5 research credit.

## Identity boundary

`TOP_N_RESULT_SET != COMPLETE_MERGED_PR_HISTORY`

`CLOSED_PR_PAGE != MERGED_PARALLAX_SEARCH_PREDICATE`

`FILTERED_WORKFLOW_ZERO != DIRECT_WORKFLOW_ZERO`

`CHECK_RUN_SUCCESS != EXACT_NATIVE_CHECKER_PASS`

`MERGED_PR_EVENT != EXTERNAL_RUNTIME_EFFECT`

Do not conflate wrapper sort, REST page index, source-time event, PR head, merge commit and current main ref. REST closed and wrapper merged-Parallax are intentionally different predicates; comparisons establish visibility and scope, not equality of result sets.

## 实验设计

### Trial A — query-window visibility

- 目的: Test whether an omitted object in a bounded merged-PR search can support a universal absence conclusion
- 保持条件: Same repository, GitHub publisher, search text and Asia/Shanghai execution date
- 改变条件: connected search result limit topn=5, 10, 30; separately inspect closed PR pages using fixed per_page=5 and explicit page indices
- 预期支持结果: A PR absent from a narrower projection is present in a larger result or directly fetched PR object
- 预期反证结果: A complete identical-predicate inventory proves true absence, or the referenced PR does not exist

### Trial B — delivery/event/check identity

- 目的: Test whether PR authoring/delivery metadata, event timeline, filtered run list and direct Checks/Actions describe the same event set
- 保持条件: Fixed PR numbers #902/#903, #903 exact head SHA, GitHub publisher
- 改变条件: per-object PR detail, event timeline, direct Actions REST, filtered connector wrapper, exact-head check-runs and current-main ancestry
- 预期支持结果: Per-object merge events and direct workflow results coexist with narrower filtered projections, with explicit distinct SHA and status semantics
- 预期反证结果: The direct event/merge identifiers disagree, or the direct workflow list is empty under the same head/time predicate

## 反例检查

The direct, merged PR #902 is not visible in the bounded topn=10 response but appears under the same predicate with topn=30, refuting the universal absence interpretation. The REST page=1 omission is also defeated by page=2, while the REST `closed` predicate does not prove these queries are identical to the merged-Parallax wrapper. Direct #903 Actions evidence refutes treating the wrapper's filtered zero as no execution. CodeQL neutral refutes flattening all returned checks to success. A tool-schema bug in the first assertion harness refutes treating a failed field lookup as a repository-state inconsistency.
