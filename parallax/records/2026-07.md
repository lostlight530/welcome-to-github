# 观察记录 2026-07

## 2026-07-20

### 研究问题

固定证据层级能否阻止把官方声明扩大成未经验证的运行结论.

### 证据

- [OpenAI Agents SDK Tracing](https://openai.github.io/openai-agents-python/tracing/), 官方技术文档, 访问日期 2026-07-20.
- [OpenAI Agents SDK Guardrails](https://openai.github.io/openai-agents-python/guardrails/), 官方技术文档, 访问日期 2026-07-20.
- [Hermes Agent Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/), 官方技术文档, 访问日期 2026-07-20.
- [OpenClaw AGENTS.md](https://github.com/openclaw/openclaw/blob/main/AGENTS.md), 官方源码仓库规则, 访问日期 2026-07-20.
- [openJiuwen](https://openjiuwen.com/en/), 官方产品与技术说明, 访问日期 2026-07-20.

### 假设

如果先标注证据层级，再形成判断，产品声明将只能产生待验证问题，不能直接升级为已实现能力或比较优势.

### 控制条件

- 只使用公开一手来源.
- 不使用项目热度、第三方评价和宣传排名.
- 每个判断必须能够回指到具体来源.

### 实验

1. 从五个来源提取追踪、护栏、会话隔离、维护边界与状态恢复相关陈述.
2. 按可运行结果、源码契约、技术文档和产品声明分级.
3. 尝试形成跨项目共同结论.
4. 删除无法由当前证据直接支持的扩大解释.

### 原始观测

- OpenAI 文档明确描述运行事件追踪和输入输出护栏，同时提示追踪可能包含敏感数据.
- Hermes 文档明确描述定时任务使用新会话、自包含提示、执行记录和防重入锁.
- OpenClaw 仓库规则明确要求依赖行为以官方文档、源码、类型和实时验证为依据.
- openJiuwen 官方页面声明状态持久化、中断恢复和全链路追踪能力，但本次没有独立运行证据验证这些声明.
- 证据分级阻止了把功能声明扩大为稳定性已经得到证明的结论.

### 反例

- 官方文档可能落后于当前实现.
- 官方源码规则说明维护要求，不等于所有运行都满足要求.
- 产品页面中的能力声明需要源码、测试或运行结果继续验证.

### 暂时结论

状态为观察. 证据分级在本次样本中阻止了一次明显的扩大解释，但单次记录不能证明它能够稳定减少错误判断.

使用不同项目和不同来源顺序重复 P-02，并记录结论是否保持一致.
