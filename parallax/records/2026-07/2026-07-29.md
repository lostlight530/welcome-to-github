## 研究摘要

本专题检查 OpenAI Status 一条账户访问事件在首次 resolved 后重新进入 monitoring, 最后再次 resolved 时, 当前判断能否随同一事件的较新更新改变

六个 Trial 从首次 resolved 快照开始, 依次加入后续 monitoring, 最终 resolved, 逆序呈现, 时间戳缺失与事件身份缺失条件

首次 resolved 只在当时快照成立

三小时后的 monitoring 更新说明账户访问已经恢复, 但订阅与额度相关影响仍在处理, 因此首次完全恢复表述不再承担该事件的当前完整状态

最终 resolved 再次成为当前状态, 中间各状态仍作为历史记录保留

删除时间戳或事件身份后, 输出拒绝确定更新归属与当前状态

本批次是 P-04 的第三个研究批次与第三个执行窗口, 完成反例检查后触发长期记录 N-03

## 研究问题

同一官方事件在 resolved 后出现更晚的 monitoring, 再次 resolved 时, 判断能否按有效时间更新当前状态并保留被替代状态的历史范围

逆序呈现, 删除时间戳或删除稳定事件 ID 时, 是否会错误坚持首次 resolved, 或把另一事件的线性恢复链复制过来

## 可证伪假设

- 支持条件: 当前判断依次采用首次 resolved, 后续 monitoring 与最终 resolved, 旧状态保留历史范围, 缺少时间戳或事件身份时拒绝确定归属
- 推翻条件: 把首次 resolved 当作永久事实, 删除中间 monitoring 历史, 按呈现位置覆盖时间顺序, 或跨事件复制当前状态

## 控制条件

- 判断对象固定为同一事件在指定快照时的当前状态
- 当前状态只由具有同一稳定事件身份且时间更晚的有效更新决定
- 被替代状态保留为对应时间范围内的历史记录
- Trial A 只提供首次 resolved 及此前更新
- Trial B 只增加首次 resolved 后第一条 monitoring
- Trial C 只增加最终 resolved
- Trial D 只逆转完整更新链的呈现顺序
- Trial E 只移除全部时间戳并打乱更新顺序
- Trial F 只移除事件 ID并混入 E3 与 E4

## 实验设计

### Trial A

- 目的: 建立首次 resolved 快照基线
- 保持条件: E1 与 E2 的事件身份和截至 16:09:19Z 的更新
- 改变条件: 不提供更晚更新
- 预期支持结果: 当前状态为 resolved, 后续是否变化未知
- 预期反证结果: 根据后见信息提前写入后续 monitoring

### Trial B

- 目的: 检查 resolved 后的 monitoring 是否替换当前状态
- 保持条件: Trial A 的事件身份与时间规则
- 改变条件: 加入 19:09:48Z monitoring
- 预期支持结果: 当前状态更新为 monitoring, 首次 resolved 保留为历史快照
- 预期反证结果: 继续把首次 resolved 写成当前完整状态

### Trial C

- 目的: 检查最终 resolved 是否再次替换当前状态
- 保持条件: Trial B 的事件身份与完整中间更新
- 改变条件: 加入 2026-06-06 06:16:40Z resolved
- 预期支持结果: 当前状态再次更新为 resolved, 中间 monitoring 保留历史
- 预期反证结果: 删除中间状态或继续停留在 monitoring

### Trial D

- 目的: 检查完整更新链逆序呈现
- 保持条件: E1 与 E2 的事件身份, 时间戳与全部更新
- 改变条件: 从最终 resolved 向 investigating 逆序呈现
- 预期支持结果: 仍以最终 resolved 作为当前状态
- 预期反证结果: 被最后呈现的早期 investigating 覆盖

### Trial E

- 目的: 检查时间戳缺失
- 保持条件: E1 与 E2 的同一事件文本和状态标签
- 改变条件: 删除时间戳并打乱更新顺序
- 预期支持结果: 无法确认当前状态, 拒绝按位置猜测
- 预期反证结果: 任意选择 resolved 或 monitoring 作为当前状态

### Trial F

- 目的: 检查事件身份缺失与线性反例
- 保持条件: 同一发布者和相似状态标签
- 改变条件: 删除事件 ID, 混入 E3 与 E4 的线性恢复链
- 预期支持结果: 无法可靠归属更新, 不把另一事件的状态路径复制过来
- 预期反证结果: 合并两条事件链并形成单一当前状态
