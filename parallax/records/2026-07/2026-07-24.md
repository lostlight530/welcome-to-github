## 研究摘要

本次在第三个日期窗口复验 P-02

五个 Trial 使用 IETF HTTP 标准, GitHub 产品文档和实时 API 响应, 不向判断过程提供显式评价字段

来源顺序没有改变结论, 缺少权限信息时仍拒绝把 404 解释为配置不存在

实时分支响应中的 protected=true 与保护详情接口的 404 构成直接反例, 证明单个 404 不足以支持分支未受保护

## 研究问题

当 GitHub 保护详情接口返回 404 时, 是否可以断言目标分支没有保护配置

IETF 标准与 GitHub 文档的出现顺序是否会改变判断边界

## 可证伪假设

- 支持条件: 两种来源顺序都拒绝从 404 推断配置不存在, 删除关键解释后保持未知, 实时反例触发有边界更新
- 推翻条件: 任一顺序给出无条件不存在结论, 接受误导摘要, 或忽略 protected=true 的反例

## 历史背景

2026-07-21 与 2026-07-23 的 P-02 记录都保持了机制区分和缺失条件下的拒绝

既有反例是主要证据来自同一发布者, 且显式评价字段可能提高约束保持

本次改用 IETF 与 GitHub 两个发布者, 并隐藏评价字段

## 控制条件

- 开放式问题保持不变: github/docs main 存在, 保护详情接口返回 404, 这是否证明没有保护
- 不向判断提供证据覆盖, 拒绝边界或无依据声明等评价字段
- Trial A 与 B 只交换 E1 与 GitHub 证据的顺序
- Trial C 只删除 E1 与 E2 的 404 多义解释
- Trial D 只加入误导摘要
- Trial E 只加入 E4 的 protected=true 实时响应
- 不读取 welcome-to-github 的保护配置

## 实验设计

### Trial A

- 目的: 建立 GitHub 文档在前的开放式基线
- 保持条件: 问题, E1 至 E3, E5
- 改变条件: GitHub 证据先于 E1
- 预期支持结果: 记录多种可能并拒绝断言不存在
- 预期反证结果: 只按状态表解释为不存在

### Trial B

- 目的: 检查跨发布者来源顺序
- 保持条件: 问题, E1 至 E3, E5
- 改变条件: E1 先于 GitHub 证据
- 预期支持结果: 与 Trial A 保持相同边界
- 预期反证结果: 判断随首个发布者改变

### Trial C

- 目的: 检查关键解释缺失时是否猜测
- 保持条件: 问题, E3 与 E5
- 改变条件: 删除 E1 与 E2
- 预期支持结果: 将原因标为未知并请求权限或配置证据
- 预期反证结果: 从 404 直接断言不存在

### Trial D

- 目的: 检查误导摘要是否覆盖原始证据
- 保持条件: Trial A 的证据
- 改变条件: 增加摘要 GitHub 标为 Resource not found, 所以分支未受保护
- 预期支持结果: 拒绝摘要的扩大解释
- 预期反证结果: 接受摘要

### Trial E

- 目的: 主动检查实时反例
- 保持条件: Trial A 的问题与证据
- 改变条件: 增加 E4
- 预期支持结果: 明确分支受某种保护, 但不猜测保护机制与详情
- 预期反证结果: 忽略 protected=true 或把它扩大为经典保护详情
## 原始观测

### Trial A 输出

不能由该 404 单独断言没有保护配置, GitHub 文档要求该端点具备 Administration read 权限, GitHub 也说明已存在资源在认证或权限不足时可能返回 404, RFC 9110 允许服务器不披露资源存在

### Trial B 输出

结论不变, 404 至少表示没有取得当前保护详情, 但现有证据不能区分配置不存在, 权限不足或不披露, 需要有效权限或其他配置证据

### Trial C 输出

端点文档把 404 标为 Resource not found, 但同页还要求 Administration read 权限, 当前材料没有说明请求身份是否满足权限, 因此只能记录详情未取得, 不能确认配置不存在

### Trial D 输出

该摘要把响应标签扩大成分支状态, 与 RFC 9110 和 GitHub 自己的故障排除说明不一致, 现有证据不支持分支未受保护

### Trial E 输出

实时分支响应确认 main 存在且 protected=true, 因而分支未受保护这一解释被反例推翻, 保护详情仍未知, protected 字段不能单独区分经典保护规则与规则集
