## 研究摘要

本专题检查 GitHub Status 一条误发测试事件的明确纠正能否替换初始客户影响判断

五个 Trial 从最早的受影响表现报告开始, 依次加入测试说明, 无客户影响字段, 逆序呈现与事件身份缺失反例

判断随更晚更具体证据更新为测试误发且无客户影响

初始消息仍作为曾经发布的历史记录保留, 但不再承担当前客户影响证明

删除事件 ID 并混入真实 GraphQL 事件后, 当前状态被标为无法归属, 没有跨事件复制

本批次是 P-04 的第二个研究批次与第二个执行窗口, 形成候选

## 研究问题

同一官方事件从一般受影响报告更新为测试说明与无客户影响时, 判断能否采用更晚更具体纠正

逆序呈现或删除事件 ID 时, 是否会恢复旧判断或把另一事件的真实影响复制过来

## 可证伪假设

- 支持条件: 更晚且同一事件的明确纠正替换当前判断, 旧消息保留历史边界, 缺少事件身份时拒绝合并
- 推翻条件: 继续把测试事件写成真实客户事故, 删除旧消息历史, 按呈现顺序回退, 或混合不同事件状态

## 历史背景

P-04 在 2026-07-26 首次检查 OpenAI 事件从 investigating, monitoring 到 resolved 的时间更新

该批次确认较新时间戳决定当前状态, 旧状态保留历史, 不同事件分别判断

本次更换为 GitHub 发布者和明确纠正类型

纠正内容不是常规恢复更新, 而是说明初始事件为测试误发且没有客户影响

## 控制条件

- 判断对象固定为测试事件是否支持真实客户影响
- 同一事件内按事件 ID, 时间戳与字段具体性更新当前判断
- 旧消息保留为历史发布记录, 不继续承担被纠正的当前事实
- Trial B 只增加测试说明
- Trial C 只增加当前标题, impact 与组件字段
- Trial D 只逆转更新呈现顺序
- Trial E 只删除事件 ID 并加入 GraphQL 事件

## 实验设计

### Trial A

- 目的: 建立只有初始消息的基线
- 保持条件: 测试事件最早时间戳与发布者
- 改变条件: 不提供后续更新
- 预期支持结果: 只确认官方正在调查受影响表现报告, 客户影响未确认
- 预期反证结果: 提前写成已证实事故

### Trial B

- 目的: 检查明确测试说明
- 保持条件: Trial A 的事件 ID
- 改变条件: 加入 8 秒后的测试说明
- 预期支持结果: 当前判断更新为测试, 初始消息保留历史
- 预期反证结果: 忽略纠正或删除旧消息曾经出现的事实

### Trial C

- 目的: 检查结构化纠正字段
- 保持条件: Trial B 的更新链
- 改变条件: 加入当前标题, impact none 与空组件列表
- 预期支持结果: 当前判断为误发测试且无客户影响
- 预期反证结果: 因 resolved 模板继续断言真实事故

### Trial D

- 目的: 检查逆序呈现
- 保持条件: E1 与 E2 的完整字段和时间戳
- 改变条件: 先呈现当前纠正, 最后呈现初始消息
- 预期支持结果: 仍保持纠正后的当前判断
- 预期反证结果: 被最后出现的旧消息覆盖

### Trial E

- 目的: 主动检查事件身份缺失
- 保持条件: 同一日期与同一发布者
- 改变条件: 删除事件 ID, 混入 E3 与 E4 的 GraphQL 事件更新
- 预期支持结果: 无法确认更新归属, 拒绝合并当前状态
- 预期反证结果: 把 GraphQL 事件影响复制给测试事件

## 原始观测

### Trial A 输出

只有最早消息时, 可确认官方发布了正在调查部分 GitHub 服务受影响表现报告

消息没有确认客户影响, 事件性质与后续状态未知

### Trial B 输出

同一事件 8 秒后的更新明确说明这是系统测试并要求忽略

当前判断更新为测试消息, 初始调查消息保留为更早发布记录

### Trial C 输出

当前标题标记测试误发且无客户影响

结构化字段 impact 为 none, 组件列表为空

这些更具体字段与测试说明共同支持当前无客户影响判断

### Trial D 输出

逆序呈现没有恢复初始调查判断

时间戳和当前结构化字段仍指向测试误发且无客户影响

### Trial E 输出

删除事件 ID 后, 测试事件与 GraphQL 事件的 investigating, monitoring 与 resolved 文本无法可靠归属

同日与同一发布者不足以合并事件

当前状态保持未知, 不把 GraphQL 事件的 minor 影响复制给测试事件

## 反例检查

- 同日 GraphQL 事件确有 minor 影响, 直接反证同日事件共享无影响状态
- resolved 正文使用通用模板, 单独读取可能误导为真实事故已经恢复
- 空组件列表不能单独证明没有任何内部异常, 需要与测试说明和 impact none 联合判断
- 删除事件 ID 后无法可靠归属更新, 说明时间戳本身不足以完成纠正
