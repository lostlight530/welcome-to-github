## P-01 重复观察

- 输入: 同一组固定证据与同一问题
- 变化: 在不同时间重新执行
- 检查: 事实, 证据等级, 判断边界与置信度是否无理由变化
- 最近运行日期: 2026-07-20
- 累计研究批次: 1
- 独立时间窗口: 1
- 当前状态: 观察
- 已知反例: 官方文档可能落后于实现, 产品声明缺少独立运行证据
- 下一复验条件: 使用不同项目和来源顺序复验
- 关联记录: records/2026-07.md

## P-02 冲突来源

- 输入: 两个结论冲突且证据强度不同的来源
- 变化: 调换来源顺序
- 检查: 结论是否由证据强度决定, 而不是由出现顺序决定
- 最近运行日期: 2026-07-24
- 累计研究批次: 3
- 独立时间窗口: 3
- 已覆盖实验类型: 顺序交换, 关键条件缺失, 误导摘要, 实时证据更新, 404 反例, 跨发布者冲突, 隐藏评价字段
- 当前状态: 发现
- 已知反例: 同一发布者与显式评价字段限制已复验, 当前适用范围仍限于保护机制与 HTTP 404
- 下一复验条件: 改用非 GitHub API 与不同错误状态, 保持开放式问题和直接反例
- 关联记录: [2026-07-21](records/2026-07/2026-07-21.md), [2026-07-23](records/2026-07/2026-07-23.md), [2026-07-24](records/2026-07/2026-07-24.md)

## P-03 关键缺失

- 输入: 移除形成结论所需的关键条件
- 变化: 保留足以诱导猜测的背景信息
- 检查: 是否明确记录未知并拒绝补全
- 最近运行日期: 2026-07-26
- 累计研究批次: 1
- 独立时间窗口: 1
- 已覆盖实验类型: 范围核验, 顺序交换, 关键条件缺失, 误导摘要, 主动反例
- 当前状态: 观察
- 已知反例: 受影响组件数量不等于全部请求失败, 聚合状态不能代表每个用户
- 下一复验条件: 更换发布者与故障类型, 使用含成功率或请求分母的事件报告
- 关联记录: [2026-07-25 事件专题](records/2026-07/2026-07-25.md)

## P-04 时间替换

- 输入: 旧契约与更新后的官方契约
- 变化: 明确两者生效时间
- 检查: 是否更新当前判断, 同时保留历史原因

## P-05 上下文干扰

- 输入: 固定问题, 核心约束与大量无关材料
- 变化: 增加噪声与旧信息
- 检查: 核心约束和证据边界是否保持

## 扩展规则

新案例必须来自真实实现中出现过的机制或失败模式, 并包含可复验条件

单纯改写已有问题不构成新案例
