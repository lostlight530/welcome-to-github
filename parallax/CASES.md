# 控制案例

## P-01 重复观察

- 输入: 同一组固定证据与同一问题
- 变化: 在不同时间重新执行
- 检查: 事实, 证据等级, 判断边界与置信度是否无理由变化
- 最近实际执行日期: 2026-08-02
- 累计研究批次: 3
- 独立执行窗口: 3
- 已覆盖实验类型: 跨时重复判断, 来源顺序交换, 关键证据缺失, 误导摘要位置交换, 冻结证据包, 可重复文本检查, 冲突访问状态, 当前访问恢复, 主动反例
- 当前状态: 发现
- 已知反例: 官方文档可能落后于实现, 技术文档与维护规则不能证明稳定运行, 文本标记命中不能证明框架行为, 追踪可以禁用且可能含敏感数据, 并行护栏失败前运行可能已经开始, 新会话具有输入与终态约束, 同一官网在不同客户端可以同时返回 HTTP 200 与 418
- 下一复验条件: 在新窗口加入相关框架的可重复行为测试, 构造行为结果与文档冲突, 分别删除行为结果, 文档正文与产品身份

## P-02 冲突来源

- 输入: 两个结论冲突且证据强度不同的来源
- 变化: 调换来源顺序
- 检查: 结论是否由证据强度决定, 而不是由出现顺序决定
- 最近实际执行日期: 2026-07-24
- 累计研究批次: 3
- 独立执行窗口: 3
- 已覆盖实验类型: 顺序交换, 关键条件缺失, 误导摘要, 实时证据更新, 404 反例, 跨发布者冲突, 隐藏评价字段
- 当前状态: 发现
- 已知反例: 同一发布者与显式评价字段限制已复验, 当前适用范围仍限于保护机制与 HTTP 404
- 下一复验条件: 改用非 GitHub API 与不同错误状态, 保持开放式问题和直接反例

## P-03 关键缺失

- 输入: 移除形成结论所需的关键条件
- 变化: 保留足以诱导猜测的背景信息
- 检查: 是否明确记录未知并拒绝补全
- 最近实际执行日期: 2026-08-01
- 累计研究批次: 6
- 独立执行窗口: 5
- 已覆盖实验类型: 历史证据缺失, 范围核验, 请求分母缺失, 维护提示核验, 发布者身份核对, 当前浏览复验, 时间条件缺失, 对象边界反例, 顺序交换, 误导摘要, 测试误发反例, 多事件身份隔离, 相似标题合并反例, 当前状态反例, 结构化字段与正文粒度冲突, 更新逆序, 事件身份缺失, 主动反例
- 当前状态: 发现
- 已知反例: 远端记录缺失不能证明没有离线工作, 受影响组件与事件对象不能证明全部请求失败, 测试误发事件不能证明客户影响, 社区恢复公告确认论坛重新可用但不能证明普通账户每项写操作已经成功, 社区维护不能证明文档站或 API 不可用, 动态事件列表的部分核验不能证明全日只有已选事件, 相邻日期的相似标题不能证明连续故障, 当前全部 operational 不能否定已解决的历史事件, impact none 与无组件标记不能删除同一事件正文中的部分用户错误
- 下一复验条件: 使用公开请求分母或成功率执行有分母更新, 取得状态 impact 字段定义, 或在普通账户会话中安全核验社区回复与点赞

## P-04 时间替换

- 输入: 旧契约与更新后的官方契约
- 变化: 明确两者生效时间
- 检查: 是否更新当前判断, 同时保留历史原因
- 最近实际执行日期: 2026-07-31
- 累计研究批次: 4
- 独立执行窗口: 4
- 已覆盖实验类型: 状态更新, 明确纠正, resolved 后 monitoring, 顺序交换, 关键状态缺失, 时间戳缺失, 事件身份缺失, 跨事件反例, 跨发布者更新, 初始未知与后续归因, 初步结论边界, 历史纠错
- 当前状态: 发现
- 已知反例: 同日事件可以具有不同当前状态, 通用 resolved 模板不能证明真实事故, 首次 resolved 后仍可能出现 monitoring, 线性恢复事件不能代表所有更新路径, 动态页面快照不能代表后续状态, 后续归因可以更新当前判断但不能把初始未知改写为当时已知, 初步调查结论不能冒充最终报告

- 检查: 核心约束, 证据计数与结论门槛是否保持
- 最近实际执行日期: 2026-07-31
- 累计研究批次: 3
- 独立执行窗口: 3
- 已覆盖实验类型: 长上下文干扰, 外部权威长文, 跨发布者复验, 单变量删除, 错误摘要位置交换, 冲突表格位置交换, 关键条款缺失, 关键要求缺失, 对象身份缺失, 冲突证据, 主动反例
