## 阅读顺序

1. METHOD.md 说明记录类型, 证据闸门与结论升级规则
2. CASES.md 保存控制案例与复验状态
3. records/YYYY-MM.md 保存每日专题与特殊专题的月度索引
4. records/YYYY-MM/YYYY-MM-DD.md 保存每日专题
5. specials/README.md 保存独立特殊专题入口
6. audits/README.md 保存周期审计入口
7. NOTES.md 只接收通过长期门槛的发现

## 记录类型

- 每日专题对应一个上海归属日期, 每个日期最多一个
- 特殊专题围绕独立公共事件建立, 不替代每日专题
- 周期审计复核已完成记录, 不构成新的研究批次或时间窗口
- 实际执行日期决定独立时间窗口
- 历史补录必须同时标明归属日期与实际执行日期

## 收录边界

- 事实必须能够追溯到公开权威来源或可复现实验
- 推断与未验证事项必须显式标记
- 宣传词, 二手转述和来源数量不能单独支撑结论
- 不保存私人信息, 内部提示词, 隐藏权重或其他目录内容

## 本地检查

运行 python parallax/tools/check.py

检查器只使用 Python 标准库, 不修改文件

## 活动维护合同

- 逻辑归属日期和真实执行日期分别记录
- 同一真实日期的多个 Trial 共享一个独立时间窗口
- 同一发布者,转载和派生摘要不增加独立来源数量
- 原始来源不可取得时允许拒绝或保持无结论
- 日报不能直接升级为长期结论,周审计是派生复核且不增加实验数量
- 历史记录不回写,新证据通过后续记录建立关系
- 旧结构的已知缺口由检查器精确兼容,不放宽未来模板

## 月度维护

月度整理不只是写汇总. 按 [方法](METHOD.md#monthly-maintenance-and-correction) 完整检查当月每日、周期审计、月度索引及相关专题,纠正正文后同步受影响的结论和引用.

使用 [月度模板](templates/monthly.md),记录覆盖清单、改动日志、验证结果与未完成项. 本轮边界与进展见 [维护日志](2026-09-02-maintenance-log.md). 不新增调度或接入宿主运行链.
