## 研究摘要

本专题核验 OpenAI 官方状态页在 2026-07-27 至 30 日连续记录的四场事件

四场事件分别涉及 ChatGPT 图像生成, API invalid_prompt 错误与 ChatGPT 会话错误

每场事件具有不同事件 ID, 独立起止时间与单个受影响组件

四场事件当前均为 resolved 与 minor

六个 Trial 检查日期顺序, 相似标题合并, 组件类别缺失, 持续全站故障摘要与当前状态反例

逆序呈现没有改变事件边界

两场图像生成事件标题相似, 但不同 ID 和不连续时间阻止把它们合并为一个连续事件

删除组件类别后只能确认官方列出单个受影响组件, 不能补全具体对象

当前 summary 接口列出 25 个组件均为 operational, 反驳当前仍处于全站故障, 但不能倒推事件期间每个用户的体验

本批次形成 P-03 的一次复发检查, 不扩大 N-02 的既有适用范围

## 研究问题

连续四天出现四场官方状态事件, 是否足以证明 OpenAI 全部服务连续四天处于故障

当事件顺序, 组件类别或事件 ID 缺失时, 判断能否保持事件边界

## 可证伪假设

- 支持条件: 四场事件各自具有稳定身份与时间窗口, 只按已列组件描述影响, 当前状态与历史状态分开
- 推翻条件: 把四场事件合并为持续故障, 从连续日期推出全部服务, 或在组件类别缺失时补出具体对象

## 历史背景

2026-07-25 特殊专题检查两场广泛错误事件是否等于全部服务失效

该专题确认事件对象, 受影响组件与请求分母不能互相替代

它适合检查连续出现是否被错误扩大为连续故障, 但状态页仍没有请求总量与失败率
