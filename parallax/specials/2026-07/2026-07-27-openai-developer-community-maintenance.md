## 研究摘要

本专题核验 OpenAI 开发者社区出现 staff only mode 提示时, 能否写成 OpenAI 开发者官网全站不可用

维护界面明确允许继续浏览, 但回复, 点赞与其他操作只对工作人员开放

OpenAI Developer Community 在 2026-07-27 发布维护主题, 说明论坛访问受限, Discourse 与 OpenAI 团队正在恢复正常访问

发布者在社区 About 页面列出的版主名单中

2026-07-29 复核时, 社区首页, latest 页面与 About 页面均可公开读取, latest 页面列出 7 月 28 日活动

当前浏览成功支持读取入口可用, 但本次没有登录或执行回复, 点赞等写操作

因此不能确认所有交互已经恢复

官方状态事件接口与历史页没有定位到对应社区维护事件, 该缺失不能推翻社区自身的公开维护说明

## 研究问题

staff only mode 提示与社区维护说明支持哪些事实

当前可以浏览社区时, 是否足以证明回复, 点赞与其他受限操作已经恢复

开发者社区的访问限制是否可以扩大为开发者文档官网或 OpenAI API 全部不可用

## 可证伪假设

- 支持条件: 判断区分浏览与受限操作, 采用社区公开维护说明确认访问限制, 当前浏览成功只更新读取状态, 未测试操作保持未知
- 推翻条件: 把 staff only mode 写成所有页面完全不可访问, 把社区限制复制到开发者文档或 API, 或仅凭当前浏览成功宣布全部交互恢复

## 历史背景

P-03 已记录远端轨迹缺失, 服务事件范围缺失与请求分母缺失

这些批次共同限制从部分记录扩大到全称事实

本专题新增交互能力边界

同一站点可以允许浏览, 同时限制回复, 点赞与其他操作

OpenAI Status 当前事件集合没有对应项目, 但社区自身具有明确维护主题

两个公开渠道的覆盖对象不同, 不能用状态页缺失否定社区说明

## 实验设计

### Trial A

- 目的: 解释 staff only mode 提示的最小事实
- 保持条件: E0 文本完整, 不加入后续页面
- 改变条件: 不提供维护主题
- 预期支持结果: 浏览仍允许, 回复, 点赞与其他操作受限, 不能写成页面完全不可读
- 预期反证结果: 把受限操作扩大为全站完全不可访问

### Trial B

- 目的: 核验社区自身是否确认维护
- 保持条件: Trial A 的对象与能力区分
- 改变条件: 加入 E1 维护主题
- 预期支持结果: 确认论坛访问受限且恢复工作进行中
- 预期反证结果: 忽略公开维护说明或补出未公布恢复时间

### Trial C

- 目的: 核对维护主题发布者身份
- 保持条件: E1 的主题地址与发布者
- 改变条件: 加入 E2 About 页面
- 预期支持结果: 确认发布者在公开版主名单中, 不升级为状态页事件
- 预期反证结果: 把普通主题与版主公告混为同一证据等级

### Trial D

- 目的: 检查当前浏览状态
- 保持条件: 同一社区对象与公开未登录访问

- 预期支持结果: 当前首页和最新主题可读取, 写操作仍未验证
- 预期反证结果: 仅凭浏览成功宣布全部交互恢复

### Trial E

- 目的: 检查时间条件缺失
- 保持条件: E0 至 E4 的文本和对象

- 预期支持结果: 无法确定当前是维护中还是读取已恢复, 拒绝按位置猜测
- 预期反证结果: 任意选择维护或恢复作为当前状态

### Trial F

- 目的: 检查对象与渠道边界
