# 方法

## 来源闸门

候选材料进入研究前必须通过以下检查.

1. 来源能够公开访问并准确定位.
2. 至少具有官方源码、正式文档、测试、追踪记录或可复现实验之一.
3. 能够提取具体机制，而不是只有愿景或宣传描述.
4. 能够说明机制的代价、失败条件或适用边界.
5. 不依赖热度、厂商规模和二手评价决定价值.

来源集合保持开放. 任何通过闸门的真实实现都可以进入研究，不设置厂商、框架或项目白名单.

## 证据层级

从强到弱依次为.

1. 可重复运行结果与测试.
2. 当前源码中的明确契约.
3. 官方技术文档与发布说明.
4. 官方产品声明.
5. 二手材料与未经验证的解释.

弱证据可以产生问题，不能单独产生长期结论. 来源之间冲突时保留冲突，并优先复验更接近实际运行的证据.

## 固定研究链

每项研究必须完整记录.

`研究问题 → 可证伪假设 → 控制条件 → 实验 → 原始观测 → 反例 → 暂时结论 → 复验条件`

事实、推断与未验证事项必须分开. 缺少关键证据时允许得出无结论结果.

## 结论状态

- 观察: 只出现一次.
- 候选: 在独立条件下重复出现，但尚未完成跨时复验.
- 发现: 至少经过三个独立实验、跨两个时间窗口并完成反例检查.
- 失效: 新证据推翻原结论，保留原记录并写明原因与日期.

只有发现可以进入 `NOTES.md`.

## 比较维度

- 证据覆盖.
- 约束保持.
- 重复判断一致性.
- 无依据声明.
- 合理拒绝.
- 纠错保持.
- 判断漂移.
- 人工复核负担.
- 验证后的有效耗时.

这些维度分别记录，不压缩成一个综合分数.

## 记录节奏

- 日记录使用 `templates/daily.md`.
- 阶段复核使用 `templates/weekly.md`.
- 周期整理使用 `templates/monthly.md`.

模板规定内容结构，不规定外部调度方式.
