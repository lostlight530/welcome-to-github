# 方法

## 来源闸门

候选材料进入研究前必须通过以下检查

1. 来源能够公开访问并准确定位
2. 至少具有官方源码, 正式文档, 测试, 追踪记录或可复现实验之一
3. 能够提取具体机制, 而不是只有愿景或宣传描述
4. 能够说明机制的代价, 失败条件或适用边界
5. 不依赖热度, 厂商规模和二手评价决定价值

来源集合保持开放, 不设置厂商, 框架或项目白名单

## 证据层级

从强到弱依次为

1. 可重复运行结果与测试
2. 当前源码中的明确契约
3. 官方技术文档与发布说明
4. 官方产品声明
5. 二手材料与未经验证的解释

弱证据可以产生问题, 不能单独产生长期结论

来源冲突时保留冲突, 优先复验更接近实际运行的证据

## 固定研究链

每个有效研究批次必须完整记录

研究问题 → 可证伪假设 → 控制条件 → 实验 → 原始观测 → 反例 → 暂时结论 → 复验条件

事实, 推断与未验证事项必须分开

缺少关键证据时允许得出无结论结果

运行缺口可以建立说明文件, 但不得补写实验, 不计入研究批次或时间窗口

历史事件在后续日期完成专题核验时, 文件日期可以使用事件归属日期

专题必须同时标明实际核验日期, 独立时间窗口只按实际核验日期计算

后续核验不得伪装成事件当天已经完成的实验

## 结论状态

- 观察: 只在一个研究批次中出现
- 候选: 在不同日期或实质不同控制条件下重复出现, 已完成至少一次反例检查
- 发现: 至少经过三个独立实验, 跨两个时间窗口并完成反例检查
- 失效: 新证据推翻原结论, 保留原记录并写明原因与日期

同一天的多个 Trial 只算一个时间窗口

结构迁移, 重新措辞和缺口记录不算独立实验

只有发现可以进入 NOTES.md

## 比较维度

- 证据覆盖
- 约束保持
- 重复判断一致性
- 无依据声明
- 合理拒绝
- 纠错保持
- 判断漂移
- 人工复核负担
- 验证后的有效耗时

各维度分别记录, 不压缩成综合分数

只有存在明确分母, 对照或可计数事件时才量化

## 记录节奏

- 每个运行日期使用 records/YYYY-MM/YYYY-MM-DD.md
- records/YYYY-MM.md 作为月度主索引
- CASES.md 保存案例累计批次, 时间窗口, 反例与下一复验条件
- README.md 只保存最新入口和状态计数
- 日记录使用 templates/daily.md
- 阶段复核使用 templates/weekly.md
- 周期整理使用 templates/monthly.md

模板规定内容结构, 不规定外部调度方式

## 连续性恢复

- 每次运行核对最早与最新日记录之间是否缺日
- 缺少可验证研究产物时建立缺口说明, 不倒填实验
- 历史事件存在可核验一手证据时可以建立专题补录
- 专题补录必须区分事件日期, 核验日期与独立时间窗口
- README 与月度索引必须同步到最新记录日期
