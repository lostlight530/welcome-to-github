# 方法

## 记录类型

### 每日专题

- 保存于 records/YYYY-MM/YYYY-MM-DD.md
- 文件日期是上海归属日期, 每个日期最多一个每日专题
- 每日专题必须包含实际执行日期与独立时间窗口
- 后续补录可以填补归属日期, 但不得伪装成当日执行
- 同一实际执行日期的多个批次共享一个时间窗口

### 特殊专题

- 保存于 specials/YYYY-MM/YYYY-MM-DD-topic.md
- 只用于具有独立公共价值的事件核验
- 必须标明事件日期, 实际核验日期与独立时间窗口
- 独立计入研究批次, 不替代每日专题, 不增加每日连续性
- 同一实际核验日期的多个专题仍共享一个时间窗口

## 来源闸门

候选材料进入研究前必须通过以下检查

1. 来源能够公开访问并准确定位
2. 至少具有官方源码, 正式文档, 测试, 追踪记录或可复现实验之一
3. 能够提取具体机制, 而不是只有愿景或宣传描述
4. 能够说明机制的代价, 失败条件或适用边界
5. 不依赖热度, 厂商规模和二手评价决定价值

来源集合保持开放, 不设置厂商, 框架或项目白名单

## 证据层级

从强到弱依次为

1. 可重复运行结果与测试
2. 当前源码中的明确契约
3. 官方技术文档与发布说明
4. 官方产品声明
5. 二手材料与未经验证的解释

弱证据可以产生问题, 不能单独产生长期结论

来源冲突时保留冲突, 优先复验更接近实际运行的证据

缺少证据不是反面证据

来源数量不是来源独立性

## 固定研究链

每个有效研究批次必须完整记录

研究问题 → 可证伪假设 → 控制条件 → 实验 → 原始观测 → 反例 → 暂时结论 → 复验条件

事实, 推断与未验证事项必须分开

缺少关键证据时允许得出无结论结果

不得把事后解释写成原始观测

## 研究批次与时间窗口

- 一个完整每日专题计为一个研究批次
- 一个完整特殊专题计为一个研究批次
- 同一批次内的多个 Trial 不增加研究批次数
- 同一实际执行日期的多个批次只形成一个时间窗口
- 结构迁移, 重新措辞与单纯缺口说明不计为研究批次
- 历史补录按实际执行日期计算时间窗口

记录数量, Trial 数量与时间窗口必须分别统计

## 结论状态

- 观察: 只在一个研究批次中出现
- 候选: 至少两个独立研究批次在不同日期或实质不同控制条件下重复出现, 并完成反例检查
- 发现: 至少三个独立实验, 跨两个实际执行窗口并完成反例检查
- 失效: 新证据推翻原结论, 保留原记录并写明原因与日期

同一天的多个 Trial 只算一个时间窗口

只有发现可以进入 NOTES.md

特殊专题可以参与案例复验, 但不能因为记录类型特殊而降低门槛

## 比较维度

- 证据覆盖
- 约束保持
- 重复判断一致性
- 无依据声明
- 合理拒绝
- 纠错保持
- 判断漂移
- 人工复核负担
- 验证后的有效耗时

各维度分别记录, 不压缩成综合分数

只有存在明确分母, 对照或可计数事件时才量化

## 连续性恢复

- 每次运行核对每日专题的日期链
- 缺少可验证同日研究时不得倒填当日实验
- 后续可以执行真实补录, 但必须写明实际执行日期
- 原缺口事实保留在历史背景与历史比较中
- 特殊专题不得用于填补每日日期链
- README, 月度索引与案例注册表必须同步

## 记录节奏

- records/YYYY-MM.md 作为月度主索引和阶段汇总
- CASES.md 保存案例累计批次, 实际执行窗口, 反例与下一复验条件
- README.md 只保存最新入口和状态计数
- specials/README.md 保存特殊专题入口
- 日记录使用 templates/daily.md
- 特殊专题使用 templates/special.md
- 阶段复核使用 templates/weekly.md
- 周期整理使用 templates/monthly.md

模板规定内容结构, 不规定外部调度方式
